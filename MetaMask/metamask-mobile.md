# Playbook: MetaMask/metamask-mobile

This is an evolving playbook. Rules are structured as itemized bullets with unique IDs to allow for incremental updates and to prevent "context collapse".

## Strategies and Hard Rules (SHR)

These are environment-specific guidelines and mandatory workflows.

- **[shr-001] Environment Setup**: To initialize the development environment, run `corepack enable` to install yarn then `yarn && yarn setup:expo`. This must be completed before running tests or the TypeScript linter (it applies necessary library patches). In headless/background runs, export `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` first — otherwise Corepack blocks forever on an interactive "Do you want to continue? [Y/n]" prompt the first time it downloads the pinned Yarn version.
- **[shr-002] Pre-Commit Validation**: Before `git push`, run `yarn lint:tsc` and ensure zero errors — required even for test-only changes (`*.test.ts(x)`). Jest + ESLint passing locally is not a substitute: `tsc`-only inference quirks (e.g. `it.each` heterogenous-union narrowing) surface only here. Re-run after every refactor, however small.
- **[shr-003] Project Type**: The project is a React Native application written in TypeScript.
- **[shr-004] Reviewer-Scope Fidelity**: When a reviewer requests a specific structure or minimal adjustment, implement exactly that requested scope first; avoid additional DRY/architectural refactors unless explicitly requested.
- **[shr-005] PR Template Compliance**: Before creating a PR, search for the repo's PR template — `metamask-mobile`'s canonical template lives at `.github/pull-request-template.md` (lowercase, hyphenated). Follow the discovered template structure in the PR body. If none is found after checking both casings, state that explicitly in the PR summary and use a minimal Summary + Testing body.

## Useful Code Snippets and Templates (CODE)

Reusable patterns and specific syntax requirements.

- **[code-001] Jest Assertion Style**: In Jest tests, use `.toStrictEqual()` instead of `.toEqual()` for comparisons.
- **[code-002] Test Description Style**: Test descriptions in `it()` should not start with 'should'.
- **[code-003] Redux Selector Default State Pattern**: Selectors that access `state.engine.backgroundState?.ControllerName` must fall back to the controller's default state to prevent crashes during app init: `state.engine.backgroundState?.ControllerName ?? getDefaultControllerNameState()`.
- **[code-004] Inline Platform Conditionals**: For simple platform-specific logic (SafeAreaView edges, small style differences), inline a `Platform.OS === 'ios' ? … : …` ternary in JSX rather than creating a utility file. Keeps diffs minimal and avoids triggering SonarCloud coverage requirements on new files. Example: `edges={Platform.OS === 'ios' ? ['left', 'right'] : ['left', 'right', 'bottom']}`.
- **[code-005] Remote Feature Flag Registration**: When adding a new LaunchDarkly flag referenced via `remoteFeatureFlags[FLAG_KEY]` / `remoteFeatureFlags.flagName` inside a selector under `app/selectors/featureFlagController/**` or `app/components/UI/**/selectors/**`, in the same PR add an entry to `tests/feature-flags/feature-flag-registry.ts` keyed on `name: '<flag-string>'`.
  - Unreleased flags: `inProd: false`, `productionDefault: false`, `status: FeatureFlagStatus.Active`.
  - Live flags: copy `inProd` / `productionDefault` from `https://client-config.api.cx.metamask.io/v1/flags?client=mobile&distribution=main&environment=prod`.
  - The registry object key may be the camelCase or quoted kebab-case form of the flag.
  - Only add the constant to `.github/scripts/known-feature-flag-constants.ts` if it is defined in a different file from where it is referenced (same-file constants resolve via `resolveConstantFromSourceFile`).
  - Validate with `yarn jest .github/scripts/check-feature-flag-registry.test.ts --coverage=false` (the full CI script requires `@actions/github` types not installed in dev).
- **[code-006] ESLint / JSDoc Conventions**: Apply these repo-wide rules up front when writing new TypeScript to avoid an extra `npx eslint` cycle:
  - `@typescript-eslint/array-type`: use `T[]` and `readonly T[]`. `Array<T>` and `ReadonlyArray<T>` are forbidden.
  - `@typescript-eslint/consistent-type-definitions`: use `interface Foo { ... }` for object shapes, not `type Foo = { ... }`.
  - `no-void`: don't prefix promises with `void`; keep the bare `.catch(...)`.
  - `jsdoc/check-indentation`: continuation lines must keep a single space after `*` — no extra indentation for list items, code blocks, or wrapped sentences. Multi-line bullets are rejected; keep each bullet on a single line or split into separate paragraphs.
- **[code-007] TanStack Query Mutation Hook Test Boilerplate**: For Jest tests around TanStack Query v4 `useMutation` hooks, override the notifyManager at module scope with `notifyManager.setBatchNotifyFunction((cb) => cb())` to avoid `unstable_batchedUpdates` teardown crashes, and clear caches in `afterEach` (`getMutationCache().clear()`, `getQueryCache().clear()`, `clear()`). Canonical example: `app/components/UI/Card/hooks/useCardFreeze.test.ts`.
- **[code-008] Minimal JSDoc style in metamask-mobile**: Do not add block JSDoc to types/functions/constants whose name + signature already conveys their intent. Reach for a comment only when there's a non-obvious trade-off, override semantic, or external reference to anchor (e.g. an OpenAPI spec URL). When a comment is justified, prefer a single `/** ... */` one-liner over a paragraph. Concrete shape this should take:
  - **Drop entirely**: block JSDoc on interfaces whose field names speak for themselves, on private helpers (`buildXyz`, `parseXyz`), on factory-style consts (`SUGGESTED_X_IDS`), and on hook wrappers that are one line of code.
  - **Keep short**: one-line comments naming an override (e.g. `/** When provided, bypass storage... */` on an optional param) or pointing at an external spec.
  - **Keep block**: only for non-obvious multi-step pipelines or constraints the implementation can't express (e.g. "stays subscribed to redux through select", "gated on feature flag X").
  - The agent's default tone of "be helpful and explain everything" produces JSDoc that obscures rather than informs; bias toward removing comments and let the code carry the meaning.
- **[code-009] Avoid cross-test rejection bleed in "inflight" chains**: for module-level serialised-write chains (e.g. `inflight = inflight.then(...)` batchers/queues), do NOT let the chain re-throw. Use `inflight = inflight.then(async () => { try { await process(batch); resolvers.forEach(r => r()); } catch (e) { rejecters.forEach(r => r(e)); } })`. Failures still propagate through the per-submit promises that the caller awaits; the inflight chain itself never rejects and therefore never leaks an unhandled rejection across test boundaries. Symptom of the bug: test B fails with "unhandled rejection" whose source pointer lands inside test A.
- **[code-010] React Compiler bailout fix recipes (behavior-preserving)**: (1) "React ESLint rules were disabled" → restructure so the suppressed rule (usually react-hooks/exhaustive-deps) is satisfied, then delete the eslint-disable; e.g. a memo reading `popularNetworks` but depending on `popularChainIdsKey` → derive `key ? key.split(',') : []`. (2) "value blocks (conditional/logical/optional-chaining) within a try/catch" → convert ternaries to if/else and `a?.b` to `if (a) { x = a.b }` INSIDE the try (statements are fine; only value-block expressions bail). (3) "Cannot access refs during render" when the ref is only WRITTEN in render and READ in effects/callbacks → move `ref.current = x` into a trailing `useEffect(() => { ref.current = x })` (no deps array), keep the `useRef(init)` initializer, and declare the sync effect BEFORE any effect that reads it. SKIP (un-tick, needs human): refs READ during render to produce rendered output (last-good-value pattern e.g. stableComparePriceRef/lastRealtimeRef); `useRef(PanResponder.create(...))` read as `.current` in render (a `useMemo(()=>create(...),[])` rewrite needs an exhaustive-deps suppression that itself bails the compiler); and BuildHIR lowering limits (try/finally, try-without-catch, ThrowStatement in try, hoisting) with no clean fix.
- **[code-011] Selector referential-stability tests must clear caches**: When asserting `toBe` across equal-content states for module-level `createSelector` / `createDeepEqualSelector` results, call `.clearCache()` on the selector under test and any upstream input selectors (e.g. `selectAllTokens.clearCache(); selectAllTokensFlat.clearCache();`) at the start of the test. Otherwise earlier suite calls leave `lruMemoize`/`weakMapMemoize` state that breaks reference equality.
- **[code-012] FlashList size styling belongs on a wrapper View (critical inside BottomSheets)**: FlashList does not apply container size styling from its own `style` prop — height caps / flex constraints set on `<FlashList style={...}>` will not bound the list, and inside a `BottomSheet` the sheet then cannot measure its content and fails to open fully (symptom: sheet opens collapsed/partially; Jest + lint pass, only reproduces on device). Wrap the list in a sized `Box`/`View` that owns the constraints and let the FlashList fill it, e.g. `<Box style={tw.style('grow shrink flex-row min-h-[200px]', 'max-h-[<Math.round(Device.getDeviceHeight() * 0.7)>px]')}><FlashList data={...} renderItem={...} keyExtractor={...} renderScrollComponent={ScrollView} /></Box>` (canonical fix: `NetworkListBottomSheet`, https://github.com/MetaMask/metamask-mobile/pull/34407). Do not copy `style`-based sizing from FlatList-based components (e.g. `NetworkSelectorList` uses RN `FlatList`, where this works).
- **[code-013] Reanimated shared values: `.value =` bails React Compiler, use `.set()` / `.get()`**: `sharedValue.value = x` produces `This value cannot be modified` (detail: `` `<svName>` cannot be modified ``) and skips the enclosing hook (even inside a `useCallback`) — compiler treats a hook's return value as immutable; `useSharedValue` is unknown to it. Fix with Reanimated's accessors — `sv.set(withTiming(target, { duration, easing }))` and `sv.get()` — on the `SharedValue` interface from 3.16 onward (repo is on 4.2.1; see `node_modules/react-native-reanimated/lib/typescript/commonTypes.d.ts`). `.set()` in a `useCallback` and `.get()` inside a `useAnimatedStyle` worklet both compile clean and pass `toHaveAnimatedStyle` assertions under Jest.
  - Only **writes** bail — `.value` reads still yield `CompileSuccess`, so converting reads to `.get()` is a per-file consistency call, not a requirement.
  - Do NOT copy `app/components/UI/RiveOnboardingStepper/useStepperProgress.ts` — it keeps `progress.value = 1` behind `// eslint-disable-next-line react-compiler/react-compiler`, forbidden by the React Compiler ticket family.
  - Before ASSETS-3736 there were zero `.set(with…)` call sites under `app/` — cite the Reanimated type definition in the PR rather than looking for a sibling file.

## Troubleshooting and Pitfalls (TS)

Lessons learned from past execution failures or resource constraints.

- **[ts-001] Jest Coverage Overhead**: Always append `--coverage=false` to individual Jest runs: `yarn jest <filepath> --coverage=false`.
- **[ts-002] Targeted Testing**: Only run tests for affected files, not the whole suite. Tests are co-located with sources (`component.tsx` + `component.test.tsx`).
- **[ts-003] Efficient Linting**: Run `npx eslint <file>` directly (the `package.json` script is slow on this repo). Format with `yarn prettier --write <file>`.
- **[ts-004] Asset.fiat Requires `conversionRate`**: `Asset` from `@metamask/assets-controllers` declares `fiat: { balance: number; currency: string; conversionRate: number }` — all three fields are required. Fixtures (e.g. `makeAsset({ fiat: ... })`) that omit `conversionRate` survive `yarn jest` and only fail at `yarn lint:tsc` at the consumer site (see `[shr-002]`).
- **[ts-005] Restore `Date.now` when testing lodash.debounce/throttle utils**: `app/util/test/testSetup.js` stubs `Date.now` to a constant (`jest.fn(() => 123)`). Any util that relies on `Date.now()` for elapsed-time tracking (`lodash.debounce`, `lodash.throttle`, manual debouncers) will never fire in tests — symptom is every test that awaits the debounced work timing out at the Jest default 5s. Restore the real clock per-suite: `const frozenDateNow = Date.now; beforeAll(() => { Date.now = () => new Date().getTime(); }); afterAll(() => { Date.now = frozenDateNow; })`.
- **[ts-006] Re-run `yarn install` after every rebase before `lint:tsc`**: rebasing onto main frequently updates `yarn.lock` (dep bumps in upstream PRs), but the long-lived `node_modules` is not touched. `yarn lint:tsc` then surfaces TS errors in files the agent never changed (e.g. `Property X does not exist on type Y` against @metamask/profile-sync-controller types). These look like real regressions but are stale-install artefacts. Always run `yarn install` immediately after `git rebase` / `git pull` before invoking `lint:tsc`.
- **[ts-007] Detect react-compiler bailouts with the babel logger, not eslint — re-probe after every fix**: ESLint `react-compiler/react-compiler` only reports a subset (mainly "skipped because a React ESLint rule was disabled"); it does NOT report "Cannot access refs during render", "value blocks within try/catch", or BuildHIR lowering bailouts — need the full compiler. Compile with `@babel/core` (`presets:['babel-preset-expo']`, `plugins:[['react-compiler',{logger}]]` — ONLY a logger, matching `scripts/react-compiler.js`; no `target`). In the logger, `kind==='CompileError'|'CompileSkip'` is a bailout, `'CompileSuccess'` optimized (one event per compiled function; module-level helper hooks count separately). Location: `event.detail.options.{reason,details[].{message,loc.start.line}}`. Throwaway script — delete before committing. Compiler stops at the FIRST bailout per function, so a ticket's stated "Failure reason" may not be the blocking one — on ASSETS-3735 all three files were listed as "Cannot access refs during render" but two were blocked by `try/finally` first, one had no ref problem. Probe before scoping, re-probe until `CompileSuccess`, call out in the PR where ticket and compiler disagreed.
- **[ts-008] `yarn test:view:base` OOMs on cloud VMs at the default heap — exits 0 anyway**: A component-view run dies with `FATAL ERROR: Ineffective mark-compacts near heap limit / JavaScript heap out of memory` around ~4GB, prints a native stack trace, still returns exit code 0 with no `Tests:` summary — reads as a pass if you only check the exit code. Distinguish from a harmless post-`PASS` teardown trace by confirming a `PASS`/`Tests:` line exists. Prefix `NODE_OPTIONS=--max-old-space-size=8192` for every `yarn test:view:base` invocation (`ExploreSearchScreen.view.test.tsx` then passes in ~135s). `yarn jest` alone does not need it.
- **[ts-009] Triage an Appium smoke failure by comparing the SAME job on other open PRs, not against main**: `Smart E2E Selection` picks specs from the diff's risk level — main green on the same job proves nothing (and main failing on a *different* Appium job is not an excuse for yours). Scan today's open PRs for one running the same shard: `gh pr list --repo MetaMask/metamask-mobile --state open --limit 25 --json number --jq '.[].number'`, then per PR `gh pr checks $pr | grep "<job name>" | awk -F'\t' '{print $2}'`. Most print nothing (`<not run>`) — selection skipped that shard; keep scanning. When you find another red one, confirm same spec AND same assertion before calling it a flake, then say so with a mechanism argument (failing element/assertion + why your diff cannot reach it) plus a passing sibling spec from the same run as harness-healthy proof.
  - `gh run view --job <id> --log-failed` returns only workflow-input echo lines — pull the full `--log` (~15k lines) and grep `✘|[0-9]\) \[android-smoke\]|failed$|passed \(` for the playwright-style summary.
  - Real failures appear twice — the runner does one automatic `Retry #1`.
  - Hundreds of `NoSuchElementError: An element could not be located` are ordinary element-polling noise, not failures.
  - Confirmed environmental flake: do NOT merge latest base to "maybe pick up a fix" — no commit fixes it and the push costs a fresh ~25 min CI cycle plus the whole Appium fan-out. Note the skip in a Jira comment; ask a human to re-run the single shard (`gh run rerun` is 403 for the agent token).
- **[ts-010] React Compiler: `??` inside a logical test bails with "Unexpected terminal kind `logical`"**: Nullish-coalescing or optional-chaining nested in a `||` / `&&` cannot be lowered, even outside a try/catch. Hoist each fallback into a local `const` above the `if` so the test is only identifiers and calls (`const fromAddress = from ?? ''; if (areAddressesEqual(fromAddress, ownAddress) || …)`). Same for a `&&` inside a `.find()` predicate — give the arrow a block body and hoist the `?? ''` onto its own line. Pure move, no semantic change.
- **[ts-011] `renderHook` + `result.current` cannot observe a transient-frame difference**: `result.current` reflects only the last committed render, so any bug an effect self-corrects on the next render is invisible; a test passes against both correct and broken implementations. When the deliberate-break check shows a new test staying green, don't weaken the assertion: re-target at a failure mode whose wrong value PERSISTS across renders (e.g. a missing guard that records a permanently wrong snapshot). If the only observable difference genuinely is one frame, push every render's value into an array from inside the hook wrapper and assert over that, or leave the branch untested and say so in the PR.
