# Playbook: MetaMask/metamask-mobile

This is an evolving playbook. Rules are structured as itemized bullets with unique IDs to allow for incremental updates and to prevent "context collapse".

## Strategies and Hard Rules (SHR)

These are environment-specific guidelines and mandatory workflows.

- **[shr-001] Environment Setup**: To initialize the development environment, run `corepack enable` to install yarn then `yarn && yarn setup:expo`. This must be completed before running tests or the TypeScript linter (it applies necessary library patches). In headless/background runs, export `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` first — otherwise Corepack blocks forever on an interactive "Do you want to continue? [Y/n]" prompt the first time it downloads the pinned Yarn version.
- **[shr-002] Pre-Commit Validation**: Before `git push`, run `yarn lint:tsc` and ensure zero errors — required even for test-only changes (`*.test.ts(x)`). Jest + ESLint passing locally is not a substitute: `tsc`-only inference quirks (e.g. `it.each` heterogenous-union narrowing) surface only here. Re-run after every refactor, however small. Also run `node_modules/.bin/prettier --check <changed files>` (CI gate `format:check`): Prettier collapses any import/line that fits within 80 chars to a single line, so hand-wrapped multi-line imports fail CI even when eslint and tsc pass. When building the changed-file list from a diff, filter out DELETED paths (e.g. `git diff --name-status <base>...HEAD | rg '^A|^M' | cut -f2`) — `git diff --name-only` includes deletions and `prettier --check` exits 2 with "No files matching the pattern" on missing paths even when all real files pass.
- **[shr-003] Project Type**: The project is a React Native application written in TypeScript.
- **[shr-004] Reviewer-Scope Fidelity**: When a reviewer requests a specific structure or minimal adjustment, implement exactly that requested scope first; avoid additional DRY/architectural refactors unless explicitly requested. Also applies to agent-initiated scope during a fix: land the minimal root-cause fix first; defer test-hardening, refactors, and "while I'm here" additions unless the user asks — during the 2026-10 token-details sticky-tabs fix, 6+ tool calls went into hardening a tautological test (walking jest-preset mock layers) before user pushback forced reverting to the one-line constant fix.
- **[shr-005] PR Template Compliance**: Before creating a PR, search for the repo's PR template — `metamask-mobile`'s canonical template lives at `.github/pull-request-template.md` (lowercase, hyphenated). Follow the discovered template structure in the PR body. If none is found after checking both casings, state that explicitly in the PR summary and use a minimal Summary + Testing body.
- **[shr-006] Never edit CHANGELOG.md in metamask-mobile feature PRs — gate it mechanically, not by memory**: The user-facing changelog goes ONLY in the PR description (`CHANGELOG entry: ...` line of the template's Changelog section — that is what mms-check validates and what the release engineer consumes). Do not add `## [Unreleased]` entries to the repo's CHANGELOG.md. Violated on PR #36360 even though this rule pre-existed and the user explicitly said not to update the changelog — the general-OSS "every PR edits the changelog" instinct beats prose rules with no enforcement. Before every push, run `git diff --name-only <base>...HEAD | grep CHANGELOG.md` (`<base>` = PR base ref, usually `origin/main`); if it prints, revert with `git checkout <base> -- CHANGELOG.md`, commit the revert, then push. If a CHANGELOG.md edit already slipped onto a PR branch, revert it in a follow-up commit on that branch.
- **[shr-007] Triage only required CI checks when babysitting PRs**: When monitoring a PR's CI (e.g. MetaMask/metamask-mobile), fix/retry failures only on required checks (the main `ci` workflow: lint, tsc, unit/view tests). Non-required failures — `check-pr-max-lines`, AI PR risk analysis, security scanners, fitness functions — are informational: report them, but do NOT refactor code or burn cycles satisfying them unless the user explicitly asks. When unsure whether a check is required, ask or leave it red with a note.
- **[shr-008] Remove `pr-not-ready-for-e2e` after static analysis passes**: metamask-mobile CI auto-applies this label to every new PR; while present, the `Check all jobs pass` aggregate job fails (~20s, log: "The 'pr-not-ready-for-e2e' label is still applied") for any PR with non-ignorable (app/) changes, regardless of real check results. Once static analysis (CodeQL, Bugbot, Security Reviewer, lint, unit tests) is green, remove it with `gh issue edit <PR#> --repo MetaMask/metamask-mobile --remove-label pr-not-ready-for-e2e` (note: PR labels are edited via `gh issue edit`, not `gh pr edit`). CI re-runs; E2E selection then decides what actually runs (often nothing for JS-only diffs). Do NOT remove it while still iterating on review feedback — that is what the label exists for.
- **[shr-009] Prior-PR file lists are the edit set, not a ceiling**: When the user says to limit a change to the files from a named PR, every file on that list still gets the corresponding edit. Do not drop a listed file because its export is consumed elsewhere. For a PR that commented a line out and `it.skip`ped the assertion, the restore is uncommenting that line and removing `.skip` on that test.
- **[shr-013] metamask-mobile PR author checklist: check ALL boxes (incl. the 3 performance ones) and never delete rows** — mms-check fails on any unchecked box. Per `docs/readme/ready-for-review.md`, checked = consciously assessed, including "considered and not applicable", not proof the action ran. When a box's action wasn't literally performed (e.g. Android testing on an iOS-only QA run), check it and state the actual basis in the PR body so nothing is implied that didn't happen.
- **[shr-014] Replying in + resolving a PR review thread**: GraphQL `addPullRequestReviewComment` rejects `pullRequestReviewThreadID`. Reply via REST instead — `gh api -X POST repos/{owner}/{repo}/pulls/{n}/comments/{commentDatabaseId}/replies -f body='…'` — then resolve with GraphQL `resolveReviewThread(input: {threadId})` where threadId is the `PRRT_…` node ID found by querying `pullRequest { reviewThreads { id comments { nodes { databaseId } } } }` and matching the numeric comment ID you were given.
- **[shr-015] iOS smoke skip on PRs is policy**: `Appium Smoke Tests (iOS)` showing `skipping` in a PR's checks is expected — PRs need an explicit iOS request (`run-appium-ios-tests` label, smoke-infra changes, or a brand-new smoke spec) per `get-requirements.yml`; Android E2E is the default PR path. Don't re-trace it; do check that `pr-not-ready-for-e2e` is absent once static analysis is green, and treat Smart E2E selection comments as informational (no reply) unless a relevant smoke tag was missed or a label is blocking runs.
- **[shr-016] Verify mobile behaviour with the skulk daemon and `skulk tool`**: do not ask for a manual pass on a device or simulator, and do not leave a send unverified because the test wallet has no balance. Drive the app with `skulk up` and `skulk tool`. For a confirmation, `skulk tool eval` the TransactionController transaction and decode `to`, `data`, and `value`: empty calldata with `to` equal to the recipient is a native transfer; calldata starting `0xa9059cbb` is ERC-20 `transfer(address,uint256)`. Screenshot Advanced details when that screen shows the same fields. A broadcast transaction is not required.

## Useful Code Snippets and Templates (CODE)

Reusable patterns and specific syntax requirements.

- **[code-001] Jest Assertion Style**: In Jest tests, use `.toStrictEqual()` instead of `.toEqual()` for comparisons.
- **[code-002] Test Description Style**: Test descriptions in `it()` should not start with 'should'.
- **[code-003] Redux Selector Default State Pattern**: Selectors that access `state.engine.backgroundState?.ControllerName` must fall back to the controller's default state to prevent crashes during app init: `state.engine.backgroundState?.ControllerName ?? getDefaultControllerNameState()`.
- **[code-004] Inline Platform Conditionals**: For simple platform-specific logic (SafeAreaView edges, small style differences), inline a `Platform.OS === 'ios' ? … : …` ternary in JSX rather than creating a utility file. Keeps diffs minimal and avoids triggering SonarCloud coverage requirements on new files. Example: `edges={Platform.OS === 'ios' ? ['left', 'right'] : ['left', 'right', 'bottom']}`.
- **[code-005] Remote Feature Flag Registration**: When adding a new LaunchDarkly flag referenced via `remoteFeatureFlags[FLAG_KEY]` / `remoteFeatureFlags.flagName` inside a selector under `app/selectors/featureFlagController/**` or `app/components/UI/**/selectors/**`, in the same PR add an entry to `tests/feature-flags/feature-flag-registry.ts` keyed on `name: '<flag-string>'`.
  - Unreleased flags: `inProd: false`, `productionDefault: false`, `status: FeatureFlagStatus.Active`.
  - Live flags: copy `inProd` / `productionDefault` from `https://client-config.api.cx.metamask.io/v1/flags?client=mobile&distribution=main&environment=prod`.
  - The registry object key may be the camelCase or quoted kebab-case form of the flag.
  - Only add the constant to `.github/scripts/known-feature-flag-constants.ts` if it is defined in a different file from where it is referenced (same-file constants resolve via `resolveConstantFromSourceFile`).
  - Validate with `yarn jest .github/scripts/check-feature-flag-registry.test.ts --coverage=false` (the full CI script requires `@actions/github` types not installed in dev).
- **[code-006] ESLint / JSDoc Conventions**: Apply these repo-wide rules up front when writing new TypeScript to avoid an extra `npx eslint` cycle:
  - `@typescript-eslint/array-type`: use `T[]` and `readonly T[]`. `Array<T>` and `ReadonlyArray<T>` are forbidden.
  - `@typescript-eslint/consistent-type-definitions`: use `interface Foo { ... }` for object shapes, not `type Foo = { ... }`.
  - `no-void`: don't prefix promises with `void`; keep the bare `.catch(...)`.
  - `jsdoc/check-indentation`: continuation lines must keep a single space after `*` — no extra indentation for list items, code blocks, or wrapped sentences. Multi-line bullets are rejected; keep each bullet on a single line or split into separate paragraphs.
- **[code-007] TanStack Query Mutation Hook Test Boilerplate**: For Jest tests around TanStack Query v4 `useMutation` hooks, override the notifyManager at module scope with `notifyManager.setBatchNotifyFunction((cb) => cb())` to avoid `unstable_batchedUpdates` teardown crashes, and clear caches in `afterEach` (`getMutationCache().clear()`, `getQueryCache().clear()`, `clear()`). Canonical example: `app/components/UI/Card/hooks/useCardFreeze.test.ts`.
- **[code-008] No comments unless crucial — supersedes any "keep short" precedent**: Bias toward **zero** comments in source. Applies to every comment shape — inline `//`, block `/* */`, JSDoc `/** */` — not just JSDoc. Reviewer feedback on this repo has been unambiguous: "do not use comments unless it is crucial — I see so much comment slop." Concrete shape:
  - **Delete by default**: JSDoc on interfaces / private helpers / factory consts / one-line hook wrappers; `// Explanation of what the code does`; `//` blocks paraphrasing the next 3 lines; `//` referencing a bug/PR/ticket URL for context.
  - **Do not add explanatory comments for fixes** — put the WHY in the **commit message** and the **PR body** (they are versioned, discoverable via `git blame` → PR → commit → ticket, and don't pollute future diffs). Do NOT copy the prior-art PR precedent of leaving a one-line "why this weird import" comment (e.g. `// Must use this to make sure scroll works inside a bottom sheet on Android` from #27295) — the maintainer has explicitly rejected that pattern going forward.
  - **Narrow carve-out — keep ONLY when ALL of these hold**: (1) the constraint is impossible to express in TypeScript / the type system / a test, AND (2) there is no upstream ticket, PR, commit, or spec URL to point at from the commit message instead, AND (3) omitting the comment would cause a maintainer to actively break the code (not just wonder why it was written that way). Even then, prefer a one-line link (`// see https://...`) over prose.
  - **Failure mode this rule blocks**: agent default of "be helpful, explain everything" produces multi-line comment blocks for one-line changes ("crypto movers network filter fix": 5 comment lines for a 2-line import diff, all removed on review). The commit message and PR body already carried the same context — the source comment was pure duplication.
  - **When in doubt, delete and lean on `git blame`.** The signal-to-noise ratio of a bare, well-named symbol tree is higher than the same tree with narrator comments.
- **[code-009] Avoid cross-test rejection bleed in "inflight" chains**: for module-level serialised-write chains (e.g. `inflight = inflight.then(...)` batchers/queues), do NOT let the chain re-throw. Use `inflight = inflight.then(async () => { try { await process(batch); resolvers.forEach(r => r()); } catch (e) { rejecters.forEach(r => r(e)); } })`. Failures still propagate through the per-submit promises that the caller awaits; the inflight chain itself never rejects and therefore never leaks an unhandled rejection across test boundaries. Symptom of the bug: test B fails with "unhandled rejection" whose source pointer lands inside test A.
- **[code-010] React Compiler bailout fix recipes (behavior-preserving)**:
  - (1) "React ESLint rules were disabled" → satisfy the suppressed rule (usually react-hooks/exhaustive-deps), then delete the eslint-disable; e.g. a memo reading `popularNetworks` but depending on `popularChainIdsKey` → derive `key ? key.split(',') : []`.
    - (1a) If the unlistable dep is a **helper function in the render body** (`const fetchX = async () => {…}` called from the effect), inline the call into the effect and list its real deps. Do NOT list the helper or a `useCallback` wrapper — re-fetches every render.
    - (1b) For a mount-only `[]` effect, adding honest deps **requires** a run-once ref guard in the same edit (`if (ranRef.current) return; ranRef.current = true;`). Without it, any object dep re-created between renders (e.g. `params?.prefill`) re-triggers the effect → `setState` → infinite loop, showing as a Jest OOM (`Ineffective mark-compacts near heap limit`), not a failed assertion.
    - (1c) Preserve "runs only when dep X transitions" semantics: guard on the tracked dep, not before it — `if (ref.current || !form.addMode) return; ref.current = true; if (form.chainId) {…}`. Guarding first latches on the mount render when the tracked dep is falsy.
  - (2) "value blocks (conditional/logical/optional-chaining) within a try/catch" → convert ternaries to if/else and `a?.b` to `if (a) { x = a.b }` INSIDE the try (statements are fine; only value-block expressions bail), or extract to a module-level helper called inside the try.
  - (3) "Cannot access refs during render" when the ref is only WRITTEN in render and READ in effects/callbacks → move `ref.current = x` into a trailing `useEffect(() => { ref.current = x })` (no deps array), keep the `useRef(init)` initializer, and declare the sync effect BEFORE any effect that reads it.
  - (4) `try/finally` (BuildHIR finalizer bailout) → keep ONLY the awaited call in the `try`, assigning to `let x: Awaited<ReturnType<typeof fn>> | undefined`; duplicate the finalizer's cleanup into both the `catch` (ending in `return`) and the success path. TS narrows the `let` after a returning `catch`, but narrowing does not survive into a closure — hoist `const y = x.data;` before any `setState(prev => …)` updater.
  - SKIP (un-tick, needs human): refs READ during render to produce rendered output (last-good-value pattern e.g. stableComparePriceRef/lastRealtimeRef); `useRef(PanResponder.create(...))` read as `.current` in render; remaining BuildHIR lowering limits (try-without-catch, ThrowStatement in try, hoisting) with no clean fix.
- **[code-011] Selector referential-stability tests must clear caches**: When asserting `toBe` across equal-content states for module-level `createSelector` / `createDeepEqualSelector` results, call `.clearCache()` on the selector under test and any upstream input selectors (e.g. `selectAllTokens.clearCache(); selectAllTokensFlat.clearCache();`) at the start of the test. Otherwise earlier suite calls leave `lruMemoize`/`weakMapMemoize` state that breaks reference equality.
- **[code-012] FlashList size styling belongs on a wrapper View (critical inside BottomSheets)**: FlashList does not apply container size styling from its own `style` prop — height caps / flex constraints set on `<FlashList style={...}>` will not bound the list, and inside a `BottomSheet` the sheet then cannot measure its content and fails to open fully (symptom: sheet opens collapsed/partially; Jest + lint pass, only reproduces on device). Wrap the list in a sized `Box`/`View` that owns the constraints and let the FlashList fill it, e.g. `<Box style={tw.style('grow shrink flex-row min-h-[200px]', 'max-h-[<Math.round(Device.getDeviceHeight() * 0.7)>px]')}><FlashList data={...} renderItem={...} keyExtractor={...} renderScrollComponent={ScrollView} /></Box>` (canonical fix: `NetworkListBottomSheet`, https://github.com/MetaMask/metamask-mobile/pull/34407). Do not copy `style`-based sizing from FlatList-based components (e.g. `NetworkSelectorList` uses RN `FlatList`, where this works).
- **[code-013] Reanimated shared values: `.value =` bails React Compiler, use `.set()` / `.get()`**: `sharedValue.value = x` produces `This value cannot be modified` (detail: `` `<svName>` cannot be modified ``) and skips the enclosing hook (even inside a `useCallback`) — compiler treats a hook's return value as immutable; `useSharedValue` is unknown to it. Fix with Reanimated's accessors — `sv.set(withTiming(target, { duration, easing }))` and `sv.get()` — on the `SharedValue` interface from 3.16 onward (repo is on 4.2.1; see `node_modules/react-native-reanimated/lib/typescript/commonTypes.d.ts`). `.set()` in a `useCallback` and `.get()` inside a `useAnimatedStyle` worklet both compile clean and pass `toHaveAnimatedStyle` assertions under Jest.
  - Only **writes** bail — `.value` reads still yield `CompileSuccess`, so converting reads to `.get()` is a per-file consistency call, not a requirement.
  - Do NOT copy `app/components/UI/RiveOnboardingStepper/useStepperProgress.ts` — it keeps `progress.value = 1` behind `// eslint-disable-next-line react-compiler/react-compiler`, forbidden by the React Compiler ticket family.
  - Before ASSETS-3736 there were zero `.set(with…)` call sites under `app/` — cite the Reanimated type definition in the PR rather than looking for a sibling file.
- **[code-014] DeeplinkManager handlers must not import modules with module-scope UI side effects**: `app/store` transitively imports every deeplink handler (store → sagas → DeeplinkManager → handleUniversalLink → handlers), so a value import running code at module scope (e.g. `TRENDING_NETWORKS_LIST` calling `getNetworkImageSource` per entry) runs inside EVERY test importing `app/store` — suites partially mocking `app/util/*` deps fail at import time with errors like `toLowerCaseEquals is not a function`, only in CI shards, not the handler's own tests. `import type` for view param types; extract value data to a side-effect-free `*.constants.ts` module (plain names/CAIP ids) both the UI list and the handler derive from (canonical example: `app/components/UI/Trending/utils/trendingNetworks.constants.ts`). Smoke-check with `yarn jest app/util/favicon/index.test.ts --coverage=false` (cheap `app/store` importer) before pushing.
- **[code-015] Plain `<ScrollView>` inside a `BottomSheet` must be imported from `react-native-gesture-handler` on Android**: `BottomSheetDialog` wraps content in a `Gesture.Pan()` for drag-to-dismiss (see `app/component-library/components/BottomSheets/BottomSheet/foundation/BottomSheetDialog/BottomSheetDialog.tsx` around L108). On Android the Pan captures vertical touches from a plain `react-native` `<ScrollView>` child — single-finger scroll fails, only two-finger scroll works (native multi-touch bypasses single-pointer arbitration).
  - Symptom: items at the bottom of the list unreachable (canonical repro: many networks; e.g. Robinhood/BTC).
  - Fix: `import { ScrollView } from 'react-native-gesture-handler';` — keep `StyleSheet` on the `react-native` import.
  - Precedent: PR https://github.com/MetaMask/metamask-mobile/pull/27295 for Bridge's Select Network sheet, inline comment `// Must use this to make sure scroll works inside a bottom sheet on Android`.
  - `FlashList` variant: combine with `[code-012]`'s sized-wrapper rule and pass `renderScrollComponent={ScrollView}` where `ScrollView` is imported from `react-native-gesture-handler` (canonical: `app/components/Views/AddAsset/components/NetworkListBottomSheet/NetworkListBottomSheet.tsx`).
- **[code-016] Plain `useQuery` from `@tanstack/react-query` for ad-hoc `fetch` TSQ hooks — do NOT import `useQuery` from `@metamask/react-data-query`**: `@metamask/react-data-query`'s `useQuery` omits `queryFn` and `staleTime` from its options because it is purpose-built to consume queries registered by a MetaMask data service on the query client (see `node_modules/@metamask/react-data-query/dist/hooks.d.mts` and `app/components/UI/Money/hooks/useMoneyVaultApy.ts`). For an arbitrary `fetch` (e.g. `https://token.api.cx.metamask.io/v3/tokens/meme/trending`, `/v1/dependencies`, any Price API endpoint not wrapped by `@metamask/assets-controllers`), import directly: `import { useQuery } from '@tanstack/react-query';` and pass `queryKey` + `queryFn` + `staleTime`/`gcTime`/`enabled`/`retry: false` yourself. Canonical precedent: `app/components/hooks/useAddNetworkIfMissing/useAddNetworkIfMissing.ts`.
- **[code-017] `stickyHeaderIndices` index constants must be updated in the same commit that moves sections between direct ScrollView children and nested slots**: Moving a section into a nested slot (e.g. StatBar into `<Price>` children, 1f54c874937) silently shifts every later direct child's index; a stale `stickyHeaderIndices` entry docks the WRONG child (symptom: the tab bar scrolls off while the tab content sticks instead). Count direct children in JSX order and update the index constant atomically. A test asserting `stickyHeaderIndices === [CONSTANT]` is tautological and cannot catch index drift — assert the child at that index actually renders the sticky element, or assert against a hardcoded literal index.
- **[code-018] Assert `stickyHeaderIndices` docks the right child — RN jest preset tree recipe**: The preset nests a ScrollView's React children two mock layers below the testID-bearing instance (`host:RCTScrollView -> comp:View content container -> host:View -> children`), so `scrollView.children.indexOf` is always 0 and naive parent-walks land on the content container. Recipe: from the sticky element's testID, walk `.parent` to the nearest ancestor that also `findAllByProps({ testID })`-matches stable sibling sections, walk up from the sticky element to that ancestor's direct child, then assert `container.children.indexOf(child)` equals the sticky index constant. Catches any section moved in/out of the direct-children list (canonical: TokenDetailsV1.test.tsx "docks the tab bar as a sticky ScrollView child").
- **[code-019] Design-system SectionHeader padding and header role**: `@metamask/design-system-react-native` 0.51.0 `SectionHeader` (confirm the installed version in `yarn.lock` before reading `main`) applies `px-4 pb-2 pt-3` and appends `twClassName` via `mergeTwClassName`, which concatenates and does not tailwind-merge. On a screen that already pads itself, pass `twClassName="px-0 pb-0 pt-0"` — twrnc applies utilities left to right, so those later classes clear the defaults. Set `titleProps={{ accessibilityRole: 'header' }}` so the title `Text` is the single header. The outer row also accepts `View` accessibility props; setting the role in both places exposes two headers. Read the component from the tag matching the lockfile (`gh api repos/MetaMask/metamask-design-system/contents/<path>?ref=refs/tags/@metamask/design-system-react-native@<version>`), and quote the URL in zsh so `?ref=` is not a glob.
- **[code-020] Do not `Number()` locale-formatted balances for has-balance gates**: `assetToToken` (`selectors/assets/assets-list.ts`) sets `balance` via `formatWithThreshold` / Intl, producing strings like `1,234,567` or `<0.00001`. `Number(balance) > 0` is NaN and hides Sell on meme TDP (`TraderPositionPnlSection`). Prefer the legacy gate `Boolean(balance) && balance !== '0'`, raw/unformatted balance, or `fiat.balance > 0`. Cover comma / threshold formats in tests. Ticket: ASSETS-4234.
- **[code-021] One nested test-id module per feature, not one file per component**: When a reviewer or a small feature needs shared test ids across several components, put them in one `testIds.ts` in the feature folder as a nested object (for example `TokenDetailsIds.overview.description`). Do not add a new `ComponentName.testIds.ts` for each component when each file would only hold a handful of strings. Leave an existing per-component `*.testIds.ts` in place unless the change is already touching it.
- **[code-022] Don't import View (or other RN names) at module scope in test files whose jest.mock factories already destructure them from requireActual**: the import turns every factory-local `const { View } = jest.requireActual('react-native')` into a new `@typescript-eslint/no-shadow` warning. For a module-scope mock that must render an RN component, alias instead: `const { View: MockSheetView } = jest.requireActual('react-native');` and use that inside the `jest.fn` body.
- **[code-023] Reanimated jest mock shape: `Easing` is direct, `Animated` is the default import, `useReducedMotion` must be added**: `react-native-reanimated/mock` spreads the catalog at top level, so use `jest.mock('react-native-reanimated', () => { const Reanimated = jest.requireActual('react-native-reanimated/mock'); return { ...Reanimated, Easing: Reanimated.Easing, useReducedMotion: jest.fn(() => false) }; })` — `Reanimated.Easing.Easing` is undefined and crashes module-scope `Easing.bezier(...)`. Components under test must `import Animated, { … } from 'react-native-reanimated'` (default import) — a named-import `Animated.View` is undefined under the mock. Inspect `node_modules/react-native-reanimated/src/mock.ts` with rg/sed (runtime requires fail on ESM/Flow).
- **[code-024] design-system `Box`: layout via `twClassName` only; dynamic colors live inside the `useAnimatedStyle` worklet**: `Box` has no `flex`/layout style props (TS2322) — use `twClassName="flex-1 h-[12px] rounded-[4px] bg-border-muted"` (precedents: SpendableBalanceSection.tsx, PermissionsSummary.tsx). `react-native/no-inline-styles` rejects literal objects in `style`, so put dynamic theme colors and static geometry into the `useAnimatedStyle(() => ({ backgroundColor, height: '100%', width }))` return with a deps array (`[backgroundColor, …]`) instead of `style={[{ backgroundColor, … }, animatedStyle]}`.
- **[code-025] PriceChart-style PanResponder: create once, refresh handlers through a method, never mutate the useState value**: `useState(() => createChartPanResponder())` where the module factory closes over a plain handlers object and returns `{ panResponder, setHandlers }`. An effect calls `chartPan.setHandlers({ updatePosition, setIsChartBeingTouched })`. Assigning `chartPan.handlers.x = …` bails with `This value cannot be modified` even inside the effect. Do not `useMemo` the responder on `updatePosition` when the parent callback is a new function each render (`Price.legacy` `handleChartInteraction`) — that replaces the granted responder mid-scrub. `updatePosition` must be `useCallback` with its real deps or `exhaustive-deps` errors because a plain function changes every render. Prove it with `expect(rerendered.props.onResponderGrant).toBe(original)` plus a later gesture that calls the new callback. The file-level `react/no-unstable-nested-components` disable does not trip `react-compiler-marker`; a `react-hooks/*` suppression does.
- **[code-026] Shared-value writes inside useEffect compile on compiler 1.0.0**: `sharedValue.value = withTiming(...)` written in a `useEffect` is not a bailout (`ResourceRing.tsx` CompileSuccess; `TokenDetailsStickyFooter.tsx` useEffect write is absent from the failure list). Writes inside `useCallback` and `'worklet'` handlers still bail with `This value cannot be modified` (StickyFooter lines 323, 352, 359, 371). Fix those with `sv.set()` / `sv.get()`. Do not rewrite an effect-only `.value =` when `react-compiler-marker@0.2.0` plus the workspace `babel-plugin-react-compiler` already reports zero failures.
- **[code-027] Omitted exhaustive-deps that must stay omitted: read them with `useEffectEvent`**: When an effect intentionally reads a value but must not re-run when that value changes (listing it would refetch, loop, or latch), wrap the read in `useEffectEvent` and call the event from the effect. Do not add the event to the dependency array. React 19.2.3 is in the app, and `useEffectEvent` is already used from effects in `PerpsModeSelectionView` and `useAdapterLifecycle`. The compiler (marker 0.2.0, plugin 1.0.0) treats this as CompileSuccess. A ref written by an earlier effect is the fallback when the omitted value is not a render snapshot the event can close over. Deleting the `eslint-disable` often reveals the next bailout in the same function (ASSETS-4322: `try/finally` in `refresh`).
- **[code-028] `failRequest` must be a function declaration**: React Compiler cannot lower `throw` written inside `try`. Extract `function failRequest(message: string): never { throw new Error(message); }` and call it from the `try`. Do not write it as `const failRequest = (message: string): never => { throw new Error(message); }`. Under this repo's TypeScript, the arrow's `never` return does not narrow the guarded binding inside `try` (`TS2345` / `TS18048` on the value after `if (!x) failRequest(...)`). The function declaration does. Verified on `ManagePriceAlertsView` (ASSETS-4323).

## Troubleshooting and Pitfalls (TS)

Lessons learned from past execution failures or resource constraints.

- **[ts-001] Jest Coverage Overhead**: Always append `--coverage=false` to individual Jest runs: `yarn jest <filepath> --coverage=false`.
- **[ts-002] Targeted Testing**: Only run tests for affected files, not the whole suite. Tests are co-located with sources (`component.tsx` + `component.test.tsx`).
- **[ts-003] Efficient Linting**: Run `npx eslint <file>` directly (the `package.json` script is slow on this repo). Format with `yarn prettier --write <file>`.
- **[ts-004] Asset.fiat Requires `conversionRate`**: `Asset` from `@metamask/assets-controllers` declares `fiat: { balance: number; currency: string; conversionRate: number }` — all three fields are required. Fixtures (e.g. `makeAsset({ fiat: ... })`) that omit `conversionRate` survive `yarn jest` and only fail at `yarn lint:tsc` at the consumer site (see `[shr-002]`).
- **[ts-005] Restore `Date.now` when testing lodash.debounce/throttle utils**: `app/util/test/testSetup.js` stubs `Date.now` to a constant (`jest.fn(() => 123)`). Any util that relies on `Date.now()` for elapsed-time tracking (`lodash.debounce`, `lodash.throttle`, manual debouncers) will never fire in tests — symptom is every test that awaits the debounced work timing out at the Jest default 5s. Restore the real clock per-suite: `const frozenDateNow = Date.now; beforeAll(() => { Date.now = () => new Date().getTime(); }); afterAll(() => { Date.now = frozenDateNow; })`.
- **[ts-006] Stale `node_modules` produces `lint:tsc` errors in untouched files — after rebases AND on cloud VM snapshots**: Rebasing onto main frequently updates `yarn.lock`, and Cursor cloud VMs booted from a prebuilt snapshot can carry `node_modules` older than the branch's lockfile, with no rebase in the session. `yarn lint:tsc` then reports errors in files the agent never changed (e.g. `Property 'query' does not exist on type 'QueryClient'`, `Property X does not exist` on @metamask/* controller types). After `git rebase` / `git pull`, run `yarn install` before `lint:tsc`. For a small review-comment fix where reinstalling is out of scope, pipe the output through `rg "<changed-file-1>|<changed-file-2>"` to prove zero errors in the diff, and say in the PR summary that the remaining errors are stale-install artefacts.
- **[ts-007] Detect react-compiler bailouts: throw a probe event at the suspected site, run the marker, expect CompileSuccess**: Suspected `useRef`-in-render bailout: add `if (someCondition) { throw new Error('PROBE_BAILOUT_TEST'); }` right at the suspect line, run `react-compiler-marker --babel-plugin-path node_modules/babel-plugin-react-compiler --log-level all <file>` and expect `PROBE_BAILOUT_TEST` in the log; delete the probe. Throwaway script — delete before committing. react-compiler-marker@0.2.0 reports every BuildHIR finally and throw in a function in one pass (ASSETS-4323: 6 failures, both handlers). It still hides the next family until those are gone: value blocks appeared only on the following run. Probe before scoping, re-probe until CompileSuccess, call out in the PR where ticket and compiler disagreed.
- **[ts-008] Bump Node heap for `yarn test:view:base` and `npx eslint` on this repo (default 4GB is not enough)**: Prefix `NODE_OPTIONS=--max-old-space-size=8192` — the default heap OOMs on both, with two different failure modes:
  - `yarn test:view:base` dies with `FATAL ERROR: Ineffective mark-compacts near heap limit / JavaScript heap out of memory` around ~4GB, prints a native stack trace, still returns exit code 0 with no `Tests:` summary — reads as a pass if you only check the exit code. Distinguish from a harmless post-`PASS` teardown trace by confirming a `PASS`/`Tests:` line exists. With the prefix, `ExploreSearchScreen.view.test.tsx` passes in ~135s.
  - `npx eslint <files>` has the same OOM but crashes loud (exit 134 + full V8 stack) — no silent "pass" risk. With the prefix, two-file diffs lint in ~17s.
  - `yarn jest` alone does not need it.
  - Run `*.view.test.tsx` only with `yarn test:view:base <file> --coverage=false` (`jest.config.view.js`). `yarn jest <file>.view.test.tsx` prints "No tests found" and exits 1, because the default `jest.config.js` ignores `.view.test.` paths.
- **[ts-009] Triage an Appium smoke failure by comparing the SAME job on other open PRs, not against main**: `Smart E2E Selection` picks specs from the diff's risk level — main green on the same job proves nothing (and main failing on a *different* Appium job is not an excuse for yours). Scan today's open PRs for one running the same shard: `gh pr list --repo MetaMask/metamask-mobile --state open --limit 25 --json number --jq '.[].number'`, then per PR `gh pr checks $pr | grep "<job name>" | awk -F'\t' '{print $2}'`. Most print nothing (`<not run>`) — selection skipped that shard; keep scanning. When you find another red one, confirm same spec AND same assertion before calling it a flake, then say so with a mechanism argument (failing element/assertion + why your diff cannot reach it) plus a passing sibling spec from the same run as harness-healthy proof.
  - `gh run view --job <id> --log-failed` returns only workflow-input echo lines — pull the full `--log` (~15k lines) and grep `✘|[0-9]\) \[android-smoke\]|failed$|passed \(` for the playwright-style summary.
  - Real failures appear twice — the runner does one automatic `Retry #1`.
  - Hundreds of `NoSuchElementError: An element could not be located` are ordinary element-polling noise, not failures.
  - Confirmed environmental flake: do NOT merge latest base to "maybe pick up a fix" — no commit fixes it and the push costs a fresh ~25 min CI cycle plus the whole Appium fan-out. Note the skip in a Jira comment; ask a human to re-run the single shard (`gh run rerun` is 403 for the agent token).
- **[ts-010] React Compiler: `??` inside a logical test bails with "Unexpected terminal kind `logical`"**: Nullish-coalescing or optional-chaining nested in a `||` / `&&` cannot be lowered, even outside a try/catch. Hoist each fallback into a local `const` above the `if` so the test is only identifiers and calls (`const fromAddress = from ?? ''; if (areAddressesEqual(fromAddress, ownAddress) || …)`). Same for a `&&` inside a `.find()` predicate — give the arrow a block body and hoist the `?? ''` onto its own line. Pure move, no semantic change.
- **[ts-011] `renderHook` + `result.current` cannot observe a transient-frame difference**: `result.current` reflects only the last committed render, so any bug an effect self-corrects on the next render is invisible; a test passes against both correct and broken implementations. When the deliberate-break check shows a new test staying green, don't weaken the assertion: re-target at a failure mode whose wrong value PERSISTS across renders (e.g. a missing guard that records a permanently wrong snapshot). If the only observable difference genuinely is one frame, push every render's value into an array from inside the hook wrapper and assert over that, or leave the branch untested and say so in the PR.
- **[ts-012] Reading CI logs while the run is still in progress**: `gh run view --log` / `--log-failed` refuse until the whole run completes, even for already-failed jobs. Use `gh api repos/<owner>/<repo>/actions/jobs/<job-id>/logs --allow-escape-sequences` (job id from `gh run view <run-id> --json jobs`) to stream a completed job's log immediately — without the flag gh refuses with "the response contains terminal escape sequences", and `gh run view --job <id> --log` fails the same way — then `rg -a "Summary of all failing tests" -A30`. Appium job logs contain a NUL byte: search with `rg -a` or `sed -n '<start>,<end>p'` windows, or rg silently stops at "binary file matches". Repo's unit-test shards fail-fast: one genuinely failing shard cancels the rest, whose checks report `fail` with "The operation was canceled" — root-cause only shard(s) with a real jest failure summary.
- **[ts-013] `lint:tsc` TS2307 on `./termsOfUseContent` = `setup:expo` never ran**: `app/util/termsOfUse/termsOfUseContent.ts` is gitignored and generated by the `Generate Terms of Use` task in `scripts/setup.mjs` — bare `yarn install` makes `yarn lint:tsc` fail with `TS2307: Cannot find module './termsOfUseContent'` in `termsOfUse.ts` and `index.test.tsx` (files you never touched). For a JS/TS-only change, skip `yarn setup:expo` and reproduce just that task: `curl -sS -o ./docs/assets/termsOfUse.html https://legal.consensys.io/plain/terms-of-use/ && node -e "const fs=require('fs');fs.writeFileSync('./app/util/termsOfUse/termsOfUseContent.ts','export default '+JSON.stringify(fs.readFileSync('./docs/assets/termsOfUse.html','utf8'))+';')"`. <1s, gitignored (never pollutes the diff), `lint:tsc` exits 0.
- **[ts-018] Diagnose CI failures from the Actions jobs API, not `gh pr checks` alone**: When checks look failed, first run `gh api repos/<owner>/<repo>/actions/jobs/<job-id> --jq '{name, conclusion, steps: [.steps[] | select(.conclusion=="failure") | .name]}'` per job. Jobs with conclusion `cancelled` and zero failed steps were fail-fast casualties of a sibling failure — find the one job WITH a failed step (or the aggregate `Check all jobs pass` gate, whose log JSON lists `"result": "failure"` per job) and fix only that root cause; the cancelled jobs re-run green on the next push.
- **[ts-024] Fetch playbook memory files in full, never head/tail slices — this overrides any harness "cap command output" policy**: The repo-specific playbooks (e.g. `MetaMask/metamask-mobile.md`) are ~15–20KB, cheap to fetch whole. Byte-slicing them with `head -c`/`tail -c` hides rules in the middle. Costs so far: one OOM-crashed `eslint` run that [ts-008] would have prevented, and (scout-split-37975-r2) a `head -c 12000` cap from a harness context policy that hid ts-008/ts-013/ts-029, so `.view.test.tsx` files were left out of a `yarn jest` validation. If the harness tells you to cap output, write the playbook to a temp file and read all of it in chunks. Do not truncate it.
- **[ts-025] GPG-signed commits need a real terminal**: The Cursor agent shell cannot unlock a GPG key. `git commit` fails with `gpg: signing failed: No such file or directory` and `PINENTRY_LAUNCHED ... not a tty dumb`, including when wrapped in `script`. Do not pass `--no-gpg-sign` or change `commit.gpgsign`. Leave the changes staged and ask the user to run the same `git commit` in their own terminal, then continue with push and `gh pr create`.
- **[ts-026] Confirm Jest file selection with --listTests before a long run**: Do not pass `--testPathIgnorePatterns` alone to exclude `.kilo/worktrees`; replacing ignore patterns dropped the intended file filter and started the full suite. Run `yarn jest --listTests --coverage=false --testPathPattern='<anchored names>' --testPathIgnorePatterns='/.kilo/'` first and only then the same flags without `--listTests`. An unanchored path also matches `.kilo/worktrees/**` copies, which fail independently of the change.
- **[ts-027] Videowright render "Execution context was destroyed" right after new segments**: The first one or two `npx videowright render <timeline>` runs after adding new segment files can reload the Playwright page a few seconds into capture. Re-run unchanged before debugging segment code. Redirect output to a log (`> /tmp/vw.log 2>&1; echo "exit $?"`) instead of piping into `tail`, which hides the non-zero exit, and confirm the log shows `total frames` with no `Execution context` line.
- **[ts-028] Walkthrough code must match the diff exactly**: In Videowright segments, set `font-variant-ligatures:none;font-feature-settings:'liga' 0, 'calt' 0;` on the scene root, because JetBrains Mono otherwise renders `=>` and `!==` as ligatures. HTML-escape every label and caption string, not just code lines, because JSX tag names such as `<Text>` disappear when inserted with `innerHTML`.
- **[ts-029] `.view.test.tsx` files must run via `yarn test:view:one`, not `yarn jest`**: the default jest config excludes `.*\.view\.test\.(ts|tsx)$` in `testPathIgnorePatterns` (they run under `jest.config.view.js`), so `yarn jest app/.../X.view.test.tsx` exits 1 with "No tests found". Run `NODE_OPTIONS=--max-old-space-size=8192 yarn test:view:one <path>` (heap per [ts-008]); add `--forceExit` if the suite passes but hangs on open handles.
- **[ts-030] A Jest suite that passes and then hangs has open handles, not a failure — rerun once with `--forceExit`**: when "Tests: N passed" is followed by "Jest did not exit one second after the run completed", do not debug or bump bash timeouts; rerun with `--forceExit` and treat the pass as the signal. CI already runs `yarn test:unit ... --forceExit` for exactly this (ci.yml ~1225). Only investigate further if the suite FAILS or hangs mid-run before printing results.
- **[ts-031] Merge first, install second on merge/babysit tasks**: when the deliverable is merging a far-ahead base (origin/main) into a PR branch, run the merge and resolve conflicts BEFORE `yarn install`/`setup:expo` — the merge updates `yarn.lock`, so installing first guarantees a stale `node_modules` ([ts-006] mode): one `lint:tsc` run full of phantom errors in untouched files AND a false-green targeted jest run against the old dependency tree. If the environment was built pre-merge, run `yarn install --immutable && yarn patch-package --error-on-fail` on the merged tree, then re-run every validation (tsc + tests) and discard the earlier results.
- **[ts-032] Address test stubs must be valid hex addresses**: when unit-testing address comparisons (`areAddressesEqual`) or stubbing `selectSelectedInternalAccountAddress` state, use valid 40-hex-char addresses (`0x1234567890abcdef1234567890abcdef12345678`). `areAddressesEqual` routes both-invalid-hex inputs into the case-sensitive non-EVM branch, so short stubs like `'0xviewer'` make case-insensitive match assertions fail even when the code is correct.
- **[ts-033] `within` is a module import, not part of render()'s result**: in @testing-library/react-native, destructure only queries (`getByTestId`, `queryByTestId`, ...) from `render(...)`; call the separately imported `within(element)` for scoped queries. `const { within } = render(...)` yields `undefined` (no TS error on destructure of an optional-ish shape) and throws `TypeError: within is not a function` at the first scoped query.
- **[ts-034] Firing `layout` on a design-system `BottomSheetDialog` in Jest**: the dialog spreads `onLayout` onto RN `KeyboardAvoidingView`, whose `_onLayout` is async and calls `event.persist()` first. Pass `persist: jest.fn()` in the event and make the assertion async: `fireEvent(el, 'layout', { nativeEvent: { layout: { height: 132 } }, persist: jest.fn() }); await waitFor(() => expect(spy).toHaveBeenLastCalledWith(132));`. Without `persist` it throws `event.persist is not a function`. Without `waitFor` the spy has 0 calls.
- **[ts-035] Never pass `-r` to rg by accident — it is the replace flag**: `rg -rn PAT` rewrites every match to the literal `n` and the mangled output still looks plausible (e.g. `react-native-safe-area-context` → `react-native-n-context`). For line numbers use `-n` only; `-r` is exclusively `--replace`. If output values look truncated or wrong after an rg call, re-check the flags before trusting or acting on the values.
- **[ts-036] Modal-wrapped design-system `BottomSheet` → wrap content in `ModalSafeAreaProvider`, never an unconditional `SafeAreaProvider`**: inside a Modal on iOS, a nested `SafeAreaProvider` overwrites the root provider's correct insets (React context flows through Modals) with a modal-window measurement, collapsing `useSafeAreaInsets().bottom` to 0 — `BottomSheetDialog`'s inset-derived footer padding vanishes and footer buttons sit flush with the sheet edge. `ModalSafeAreaProvider` (app/component-library/components-temp/ModalSafeAreaProvider, PR #35025) nests only on Android (where a Modal is its own window and the root provider reads 0) and passes through on iOS; navigation-mounted sheets need no wrapper. Unit tests can't catch this: app/util/test/testSetup.js flattens insets to {0,0,0,0} — device-QA-only regression.
- **[ts-037] gh api GraphQL: use `-F` (typed) for non-string variables, `-f` (raw) only for strings**: `gh api graphql -f n=37975` sends `"37975"` and fails type coercion for `Int!`/`Boolean!`/`Float!` variables (`Could not coerce value "37975" to Int`). Pass `-F n=37975` (or `-F var=bool` / `-F var=1.5`) for type inference; keep `-f` for `String!` variables and `-f query=...` for the query itself.
- **[ts-038] Carve PR slices with merge-base diffs, never whole-file checkout**: When moving part of a PR onto a fresh branch off `origin/main`, run `git diff origin/main...origin/<pr-branch> -- <paths> | git apply --index` (three dots = since merge base). `git checkout origin/<pr-branch> -- <file>` copies the PR's whole file and silently reverts anything main added since the PR last merged main (seen on `Perps.testIds.ts` while splitting #37975). Confirm with `git diff --cached --stat origin/main` that the slice holds only additions you expect.
- **[ts-039] Stop when the Atlassian MCP namespace is absent**: A Jira-gated ticket (live status, assignee, `human-only` check) cannot be verified from the webhook snapshot. `GetDynamicTools` with no `atlassian` namespace and no `needsAuth` entry means the plugin's static skills do not provide `getJiraIssue`. Anonymous `GET https://consensyssoftware.atlassian.net/rest/api/3/issue/<KEY>` returning 404 is the private-project response, not proof the key is wrong; an `mcpgateway` JWT in `CONSENSYS_MCP_API_TOKEN` is no substitute once `exp` is past. Stop with no code changes, no PR, no transition; report the missing live read. Distinct from a namespace present but `needsAuth` (that one can become ready later).
- **[ts-040] Re-check the Atlassian namespace at the start of every Jira run**: A sibling run the same day can see no `atlassian` tools while the next run has `getJiraIssue` immediately. Call `GetDynamicTools` for that namespace before concluding Jira is unreachable. If it is ready, the live ticket (status, assignee, labels) is the eligibility source, not the webhook snapshot and not an earlier run's memory that the namespace was missing. If it is absent or `needsAuth` after a retry, follow the stop-and-report rule and do not implement from the snapshot.
- **[ts-041] Install react-compiler-marker outside the repo**: `metamask-mobile/.npmrc` sets `offline = true`, so `npx -y react-compiler-marker` inside the repo fails with `ENOTCACHED`. From `/tmp`, `npm install react-compiler-marker@0.2.0 --offline=false --no-fund --no-audit`, then run `/tmp/node_modules/.bin/react-compiler-marker --babel-plugin-path <repo>/node_modules/babel-plugin-react-compiler` with the scan directory relative to the repo. Epic ASSETS-4316 uses marker 0.2.0 as the source of truth. It lists every ref-during-render site, not only the first bailout.
- **[ts-042] A React Compiler scan row can be a false positive — stop when the marker is clean**: Before editing, run `react-compiler-marker@0.2.0` with `--babel-plugin-path node_modules/babel-plugin-react-compiler` on the file's directory (repo `.npmrc` is `offline=true`; install the marker from `/tmp`). If the target file has zero failures and is unchanged since the scan commit, do not edit it and do not open a PR. Leave a Jira comment with the CompileSuccess counts and move the ticket to Blocked for a human to cancel or rescan. Confirm the marker still flags a known-bad sibling (for example `TokenDetailsStickyFooter.tsx`) before calling the scan wrong. ASSETS-4320 / ResourceRing.tsx.
