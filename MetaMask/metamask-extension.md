# Playbook: MetaMask/metamask-extension

This is an evolving playbook. Rules are structured as itemized bullets with unique IDs to allow for incremental updates and to prevent "context collapse".

## Strategies and Hard Rules (SHR)

These are environment-specific guidelines and mandatory workflows.

- **[shr-001] Environment Setup**: `nvm install && corepack enable && yarn install`, then pin Node to the **literal `.nvmrc` version** (not `nvm current`): `export PATH="$HOME/.nvm/versions/node/v<version>/bin:$PATH"; hash -r`. `nvm use` alone loses to `/exec-daemon/node` (Node 22) on PATH; `$(nvm current)` chained after `nvm install` returns the *pre-install* version — wrong pin fails `yarn install` with `"current Node version X does not satisfy the required version"`. Verify with `node --version` before yarn. Also `export COREPACK_ENABLE_DOWNLOAD_PROMPT=0` (see `[ts-005]`). **Decide with `ls -d node_modules`, not the log**: `/tmp/cursor/async-install/install-user.log` saying `"Started from stale build ..., skipping install script"` means no repo has `node_modules`, but `/tmp/cursor/` may be **missing entirely** (background setup never scheduled) — a missing log is not evidence that install succeeded. Run install in tmux (~1–3 min, redirect to a file) and keep editing while it runs; the repo is fully readable/editable without `node_modules`.
- **[shr-002] Pre-Commit Validation**: Before pushing any code, you must execute `yarn lint:tsc`. Commits are only permitted if this check passes with zero errors.
- **[shr-003] Dependency Upgrade Scoping**: When upgrading dependencies, only modify `package.json` and `yarn.lock`. If TypeScript or lint errors appear in other files, verify they are directly caused by the upgrade before touching them. Pre-existing issues should not be addressed in the upgrade PR.
- **[shr-004] Cloud Task Instructions Priority**: When Cloud Agent instructions require committing, pushing, or running tests, follow those requirements even if repo-level `AGENTS.md` says not to commit/stage by default.
- **[shr-005] Search for in-flight PRs before implementing an issue fix**: Popular MetaMask issues often already have a community PR open. Before coding, run `gh api -X GET search/issues -f q='repo:MetaMask/<repo> is:pr is:open in:title <fix keywords>'` and search the issue number itself (`q='repo:... <issue-number>'`) to catch duplicates; call out any duplicate PR in the summary and PR body so the reviewer can pick.
    - Unquoted `in:title` with the *fix* phrasing (`in:title ERC-1155 transfer amount` found the PR after three keyword searches found nothing).
    - Read the issue number off a matching PR's `Fixes #N` line instead of hunting the issue separately — satisfies `[shr-002]` traceability in one call.

## Useful Code Snippets and Templates (CODE)

Reusable patterns and specific syntax requirements.

- **[code-001] Mocha Type Fix**: When using `it.each` for table-driven tests, prepend the call with a TypeScript override to avoid type-definition errors, and annotate the callback arguments explicitly. The `@ts-expect-error` suppresses `it.each` itself, so parameter inference becomes implicit `any` (TS7031) unless the callback is typed. _Reference:_ `ui/components/app/alert-system/utils.test.ts`.

  ```typescript
  // @ts-expect-error This is missing from the Mocha type definitions
  it.each(cases)('handles $type', ({ type }: (typeof cases)[number]) => {
    // ...
  });
  ```
- **[code-002] Arc / Stable dual-identity gas tokens (USDC, USDT0)**: On Arc (`0x13b2`/`eip155:5042`) the native gas token IS USDC; the same balance also exists as ERC-20 at `0x3600000000000000000000000000000000000000` (Stable: USDT0 at `0x779ded0c9e1022225f8e0630b35a9b54be713736`). Accounts API returns both: native `eip155:5042/slip44:5042` @ 18 decimals, ERC-20 @ 6 decimals, identical amounts, both priced. Never "unify" the two — they are deliberately opposite:
    - Asset-list / send keeps **native**, hides ERC-20 via `ui/components/app/assets/enablement/networks-customization.ts`.
    - Swap / bridge does the reverse: hides **native** via `BRIDGE_ASSET_PICKER_HIDDEN_ASSETS` in `shared/constants/bridge.ts` (router only validated for the ERC-20).
    - Under assets-unify-state the native row is *derived*, not stored: `getAccountTrackerControllerAccountsByChainId` in `shared/lib/selectors/assets-migration.ts` (mirrored in mobile `app/selectors/assets/assets-migration.ts`) emits it only when `AssetsController.assetsInfo[assetId].type === 'native'`, seeded from `packages/assets-controller/src/defaults.ts`. Any filter that removes the ERC-20 must first confirm the native entry is present — otherwise the token drops from the list while `assetsBalance` still counts it (ASSETS-3900).
    - `useArcDefaultTokens` (both clients) imports the ERC-20 id into custom assets, so manual import of `0x3600...` reports `"token already added"`.
- **[code-003] Module-level in-flight request cache**: Reset a de-dup promise with `.finally()` on the *assigned* promise (`refreshPromise ??= doFetch().finally(() => { refreshPromise = undefined; })`), never a `finally` block inside an IIFE. A sync throw in the async prologue makes the inner `finally` run before the assignment, permanently pinning a settled promise so the request never retries. Cover with a "retries after failure" test. _Reference:_ `shared/lib/token-api/supported-networks.ts`.
- **[code-004] assets-unify-state hide invariant**: Hiding a token MUST set `assetPreferences[assetId].hidden` via `AssetsController.hideAsset` (dispatch `actions.hideAsset(toAssetId(address, chainId))`). `removeCustomAsset` is NOT a hide: `shared/lib/selectors/assets-migration.ts` derives `allTokens` from `assetsBalance ∪ customAssets` but derives `allIgnoredTokens` only from `assetPreferences[*].hidden`, and `addCustomAsset` seeds a zero-balance `assetsBalance` entry — assets dropped from `customAssets` stay visible. `@metamask/assets-controllers` `selectAllEvmAssets` / `selectAllMultichainAssets` skip only assets in `allIgnoredTokens` / `allIgnoredAssets`. Mirror `ui/pages/token-management/token-management.tsx`: dispatch `ignoreTokens` / `multichainIgnoreAssets` **and** `hideAsset` unconditionally. Writes gated on compile-time `ASSETS_UNIFIED_STATE_ENABLED` (true in `builds.yml`); reads additionally gated on remote `assetsUnifyState` — write-side bugs reproduce only for rollout users (reads as flakiness in reports). Keep addresses checksummed end-to-end (`normalizeAssetId`, `toChecksumHexAddress`); lowercasing silently breaks the `includes()` filter.

## Troubleshooting and Pitfalls (TS)

Lessons learned from past execution failures or resource constraints.

- **[ts-001] Memory-Efficient Testing**: When running specific tests via `yarn jest <path>`, if the process encounters RAM memory limits, prepend the command with `NODE_OPTIONS=--max-old-space-size=4096`. Note that the full `yarn test` suite is prone to timeouts.
- **[ts-002] Jest Coverage Overhead**: Always append `--coverage=false` when running individual Jest tests to reduce execution time and resource consumption.
- **[ts-003] Ticket attachments unreachable — reconstruct state from public MetaMask APIs**: Jira / Slack attachments cannot be downloaded on a Cursor Cloud VM (Jira attachment REST → 403 without an Atlassian token, Atlassian MCP has no attachment tool, `FetchMcpResource` → 404, Slack DM → `channel_not_found`). Don't burn calls. Pull the address from the ticket and query directly:
    - `https://accounts.api.cx.metamask.io/v5|v6/multiaccount/balances?accountIds=eip155:<chain>:<address>&networks=eip155:<chain>` — exact CAIP-19 asset IDs, decimals, balances the client will persist.
    - `.../v2/accounts/<address>/balances?networks=<decimalChainId>` — v2 shape.
    - `.../v1/supportedNetworks` — chain coverage.
    - `https://price.api.cx.metamask.io/v3/spot-prices?assetIds=<caip19,...>&vsCurrency=usd` — pricing.

    Stronger evidence than a state dump: shows what the controller *will* receive. Note: `$JIRA_INTEGRATION_PLAYBOOK_URL` may hold a **local machine path**, not a URL — probe with `${VAR:0:30}` (full value is redacted in tool output) and skip if not fetchable.
- **[ts-004] Use the Grep tool, not shell `rg`, when match text matters**: `rg` via the Shell tool can return output with *matched substrings replaced* — searching `0x3600...|ARC_USDC|eip155:5042` returned lines where `ARC_USDC_ERC20_TOKEN_ADDRESS` had become `n_ERC20_TOKEN_ADDRESS` and every address / CAIP id had become a bare `n`. Paths and line numbers stay correct, so shell `rg` is still fine for "which files mention this" — never trust it for reading identifiers, addresses, or asset IDs. Use the Grep tool (correct rendering, supports `-C` / `glob` / `type`); fall back to reading the file.
- **[ts-005] Corepack download prompt silently hangs `yarn install`**: On cloud VMs, `corepack enable && yarn install` blocks forever on Corepack's interactive `"Corepack is about to download yarn@x.y.z … Do you want to continue? [Y/n]"` prompt. Piping stdout (e.g. `| tail -40`) hides the prompt — looks like a slow fetch. Always `export COREPACK_ENABLE_DOWNLOAD_PROMPT=0`; prefer the vendored binary via `yarn yarn-binary:hydrate` (`corepack hydrate .yarn/yarn-corepack.tgz --activate`) so no download runs. Diagnose with `ps -o pid,etime,time,args -p <pid>`: `TIME 00:00:00` after many minutes of `ELAPSED` = blocked on stdin, not working. Prefer `yarn install > /tmp/yarn-install.log 2>&1` over piping to `tail` — keeps prompts and progress inspectable.
- **[ts-006] Use `gh api search/issues`, not `gh issue list --search`, on cloud VMs**: Read-only cloud `gh` makes `gh issue list --search "..." --json number,title,url` exit 0 with placeholder rows (`[{"number":0,"title":"","url":""}]`) — silent, not a failure. Use instead: `gh api -X GET search/issues -f q='repo:<owner>/<repo> is:issue <terms>' --jq '.items[] | "\(.number) | \(.state) | \(.title)"'`. Search is fuzzy (quoted `in:title` phrases often ignored); no matches may mean Jira-only — MetaMask webhook reports use `[url|url]` markup and often have no GitHub issue. Then satisfy `[shr-002]` by describing the report in the PR body, not inventing an issue number.
- **[ts-007] `yarn lint:eslint <paths>` is not scoped — it lints the whole repo**: Package script hardcodes `eslint .`, so paths you pass are appended to `.` rather than replacing it. On a fresh cloud VM (cold `node_modules/.cache/eslint` cache) a "3-file lint" takes ~10 min wall / ~12 min CPU and prints nothing until it finishes — looks like a hang. Confirm with `ps -eo pid,etime,time,args | grep eslint` (growing `TIME` column means it is working, not blocked). For scoped linting use `yarn lint:changed:fix` (git-changed files, ~1s for a few files) or call the binary: `NODE_OPTIONS='--max-old-space-size=6144' npx eslint <paths> -c ./.eslintrc.js`. `yarn lint:changed:fix` prints only the oxfmt formatter summary ("Formatting and linting N changed files"); full-repo `yarn lint:eslint` is still the way to be certain ESLint is clean before pushing — budget the time and start it in tmux alongside other work.
- **[ts-008] Extension dependency changes cascade into LavaMoat/e2e failures**: Any change to `yarn.lock` (preview aliases, dep bumps, dedupe) can invalidate the checked-in LavaMoat runtime policies. Symptom: all e2e-chrome/firefox jobs fail fast with `.controller-loaded` timeout while builds and unit tests pass — a stale policy blocks a module at boot. The log line just above the timeout is the real error, for example `Policy does not allow importing @metamask/assets-controllers from @metamask/assets-controller`. Always run `yarn lint:lockfile:dedupe` (fix with `yarn dedupe`) and regenerate ALL policies via `yarn lavamoat:auto` (needs ~16GB RAM; takes ~20 min), then commit the regenerated `lavamoat/**/policy.json`. Do not skip regeneration because an older bump commit's policy diff is already on main: deduping two copies of a package (assets-controllers 112.2.0 plus 113.0.0 into a single 113.0.0) renames the compartment from `@metamask/assets-controller>@metamask/assets-controllers` to `@metamask/assets-controllers`, and main's policy still names the nested one. Diagnose by comparing `validate-lavamoat-policies` job conclusions across runs. Never assume this e2e signature is infra flakiness without checking sibling PRs' identical failures.
- **[ts-009] Extension state-shape changes require e2e fixture updates**: New controller state fields break (1) `test/e2e/tests/settings/state-logs.json` (add key + wildcard descriptor, e.g. `"field": {"*": "string"}`) and (2) `test/e2e/tests/metrics/state-snapshots/errors-after-init-opt-in-ui-state.json` (add `"field": "object"` masked entry, alphabetical). Background snapshots unaffected for `persist:false` fields. Also add required fields to `selectAssetsControllerStateForBalances` in `ui/selectors/assets.ts`, and remember `jsdoc/require-param` applies to JSDoc'd test helpers.
- **[ts-010] Caret bumps float on a lockfile merge**: After a `yarn.lock` conflict, do not `yarn install` from main's lockfile alone when the branch already locked a caret range below the newest release. Yarn treats the unsatisfied range as new and picks the highest match (for example `^20.0.2` becomes 20.1.0).
    - Restore main's lockfile, `yarn install --mode=update-lockfile`, then pin each intended locator with `yarn set resolution <pkg>@npm:<range> npm:<exact>` using one descriptor from the key, not the comma-joined key.
    - Re-run `yarn install`; confirm with `yarn install --immutable` plus `yarn dedupe --check`.
    - `yarn up -E` is the wrong tool: it rewrites the manifest to an exact version and still floats transitive ranges.
- **[ts-011] Mock RPC responses for mm E2E via direct HTTP, not the broken mock-network CLI**: The mm CLI's mock-network subcommand (as of the current @metamask/client-mcp-core) fails with VALIDATION_ERROR/crashes. To mock RPC responses for an E2E session, POST directly to the daemon instead: read the port from the `.mm-server` file in the workspace root, then POST to `http://localhost:<port>/tool/mock_network` with header `Content-Type: application/json` (required — omitting it returns VALIDATION_ERROR) and a JSON body of `{"action":"add","rule":{...}}` (matching the tool schema: method, url, response{status,headers,body}). Useful poison rule for testing RPC stalls: `{"id":"poison-rpc","method":"POST","url":"https://rpc.pulsechain.com/","response":{"status":200,"headers":{"Content-Type":"application/json"},"body":"not-valid-json-rpc"}}`. Actions: add / clear / requests (with limit). Verify rules hit with action=requests.
- **[ts-012] mm daemon's anvil occupies port 8545 — run `mm cleanup` before jest controller tests**: The mm daemon starts an anvil instance on port 8545. `metamask-controller.test.js` (and any suite binding 8545) then fails with listen EADDRINUSE. Run `mm cleanup` (or stop the daemon) before running controller unit tests in the same shell session; the failure looks like a flaky test but is a port conflict.
- **[ts-013] mm CLI quirks — navigation, screenshots, fixtures, popups, CDP**: mm CLI gotchas that cost multiple tool calls each:
  - The extension home page URL is `home.html` — navigating to `home.htm` yields `chrome-error://chromewebdata`; `mm navigate-home` is the reliable way back.
  - `mm screenshot <path>` ignores the given path and writes an auto-named file under `test-artifacts/screenshots/`.
  - Fixtures (seeded wallets, `--state`) only work with `--context e2e` — prod context has no fixture support; use e.g. `mm launch --context e2e --state default --extension-path dist/chrome`. Fixture password: `correct horse battery staple`.
  - Extension confirmations (wallet_watchAsset approval, deep-link interstitials) open in a separate popup tab — reach them with `mm switch-to-tab --role notification`, then switch back.
  - CDP `Runtime.evaluate` across repeated calls collides on top-level `const` — wrap snippets in an IIFE.
  - In build-test (LavaMoat) extension pages, `self` is not defined — use `globalThis`.
- **[ts-014] Legacy `.js` jest test files reject TS syntax and `no-empty-function`**: When adding tests to an existing `.js` jest file (e.g. `app/scripts/metamask-controller.test.js`), TS casts like `as never` fail to parse — babel raises SyntaxError `Unexpected token, expected ,`. Write plain JS (use `jest.fn()` and pass it where never is expected via a plain variable, or cast via `@ts-expect-error` if the file allows). Also ESLint's `no-empty-function` fires on `()=>{}` — for a promise that must never settle, use `new Promise(() => undefined)`.
- **[ts-015] check-pr-max-lines is an advisory size signal, not a required check**: The `check-pr-max-lines` workflow fails any PR over MAX_LINES=1000 changed lines (additions+deletions vs base; no exclusion for tests; ignores only lock/snap/lavamoat-policy/agent-dirs). It is NOT a required status check — branch rules only require the block-stable job + merge queue — and merged size-XL PRs routinely fail it (e.g. #47881, 2713 additions). It auto-applies size labels (XS<10, S<100, M<500, L<1000, XL). When it fails a large intentional feature PR: verify it is the ONLY failure, cite a merged precedent, and document it in the PR — do not panic-split the PR or treat it as blocked.
- **[ts-016] Every new route must be registered in the E2E ROUTE_PAGE_OBJECT_REGISTRY**: Adding a route to ROUTES (`ui/helpers/constants/routes.ts` + `routes.component.tsx`) fails the unit-test shard via `test/e2e/route-registry/route-registry.test.ts` ('lists every route in ROUTES') — the failure surfaces only in CI unless you run that suite locally. Fix: add the route path to `ROUTE_PAGE_OBJECT_REGISTRY` in `test/e2e/route-registry/route-registry.ts` — use `null` when no E2E page object exists yet (precedent: security-trust, market-insights) or `NOT_A_SCREEN` when the route renders no screen. Route paths must match the ROUTES constant exactly (e.g. `/asset/:chainId/:asset?/:id?/market-insights`).
- **[ts-017] New API hosts contacted during E2E must be added to privacy-snapshot.json**: E2E shards (chrome + firefox) fail with `A new host not contained in the privacy-snapshot received a network request` when new background/controller code contacts an API the snapshot does not list (here: `digest.api.cx.metamask.io` fetched by the AiDigestController-driven entry card on the asset page, breaking unrelated specs like `multichain/asset-list.spec.ts`). Fix: add the host to `privacy-snapshot.json` (repo root, alphabetically sorted JSON array; keep prettier formatting + trailing newline) — the error message also offers `--update-privacy-snapshot`. Check this whenever a PR adds any network-touching feature, even if the failing specs look unrelated to the diff.
- **[ts-018] SonarCloud S9383 on fire-and-forget trackEvent — use `.catch(() => undefined)`, never `void`**: SonarCloud's new-code quality gate fails (new_reliability_rating C) on unawaited promises (typescript:S9383) for fire-and-forget `trackEvent(...)` calls from useAnalytics (returns `Promise<void>`). The repo pattern is `trackEvent(builder.build()).catch(() => undefined);` — precedent: `ui/helpers/utils/network-management-metrics.ts` from #47880. Do NOT use the `void` operator in `ui/` code: eslint `no-void` is an error there ('off' applies only to development/webpack overrides). Test mocks must then match the real signature or `.catch` throws on undefined: `const mockTrackEvent = jest.fn((_built: AnalyticsEvent) => Promise.resolve());` (import type AnalyticsEvent from `shared/lib/analytics/create-event-builder` for the `.mock.calls[0][0]` typing to work).
- **[ts-019] Stacked branches cut from pre-fix heads inherit CI failures — port the precedent fix minimally**: A base branch stranded off an old part-1 head (ae9299681f5) that predated the final stack's stylelint fix (#47988's file-level color-no-hex disable for the entry-card chrome hex colors) makes `yarn lint`/Test lint fail on base-inherited code your diff never touched. When a stacked PR fails CI in files outside your diff: `git log <base>..HEAD -- <file>` (empty = inherited), confirm the fix that landed later in the parallel/newer stack, and port that exact fix minimally rather than reworking the file or waiting on the unmaintained base. Also useful: fetch the newer stack branch and `git show <newer-branch>:<file>` to copy the fixed pattern. Raw CI job logs that gh refuses: `gh api repos/<org>/<repo>/actions/jobs/<id>/logs --allow-escape-sequences` then strip ANSI with perl (`gh run view --log` can keep failing with `stream error; CANCEL`).
- **[ts-020] mm anvil seeding — custom mnemonic, HST mint quirk, ethers from node_modules**: The `mm` daemon runs anvil with the fixed mnemonic `spread raise short crane omit tent fringe mandate neglect detail suspect cradle` (chain 1337, port in `.mm-server` → `subPorts.anvil`); the first derived account (`m/44'/60'/0'/0/0`) is the extension wallet and the default foundry keys are unfunded (deploying from the well-known `0xac09...` key fails with a misleading viem `ExecutionRevertedError: Out of gas: gas required exceeds allowance: 0` at estimateGas — not an obvious insufficient-balance error). Deploy custom-symbol ERC20s with `ethers` v5 from the repo's node_modules using `@metamask/test-dapp/dist/constants.json` `hstAbi`/`hstBytecode` (HumanStandardToken, constructor `(initialAmount, name, decimals, symbol)`) — no forge/solc needed. The HST constructor mints `initialAmount * 10^decimals` to the deployer, NOT plain `initialAmount`, so `factory.deploy(100, 'Microsoft', 18, 'MSFT')` leaves the wallet with exactly 100 MSFT.
- **[ts-021] Enabling remote feature flags in mm e2e sessions (perps) — CDP toggle, dev-env flags, stateHooks probes**: Flag-gated features (perps) never render in `mm launch` fixtures because basic functionality (external services) is OFF and `RemoteFeatureFlagController` only fetches when onboarding is complete AND `useExternalServices` is true:
  - Flip it via CDP (plain `mm click` on `basic-functionality-toggle` is pointer-intercepted by an overlay): `mm cdp Runtime.evaluate '{"expression":"document.querySelector(\"[data-testid=basic-functionality-toggle]\").click()","returnByValue":true}'` (Settings → Privacy).
  - Verify via `window.stateHooks.store.getState().metamask` (exposed on test builds): `useExternalServices`, plus perps keys inside `remoteFeatureFlags` (fetch takes ~5-10s after the toggle).
  - The dev-environment client-config flags are the ones a `yarn start:test` build fetches and they enable perps fully: `perpsEnabled:true`, `perpsEnabledVersion {enabled, min 13.30.0}`, `perpsTerminalBackendEnabled {enabled, min 13.40.0}`, `perpsHip3AllowlistMarkets "xyz:*"`, geo-block list EMPTY (prod blocks US/BE/GB/CA-ON/CU/IR/KP/SY — so visual perps testing must use the dev environment, not prod flags).

  - `window.stateHooks` (test builds) also exposes `reloadExtension`, `submitRequestToBackground`, `getPersistedState` — a richer probe surface than describe-screen for state checks.
  - The background HIP-3 fallback allowlist `['xyz:*']` is hardcoded in `app/scripts/messenger-client-init/perps-controller-init.ts` (clientConfig.fallbackHip3AllowlistMarkets), so `xyz:*` markets survive even when the remote allowlist flag is blank.
- **[ts-022] Custom-token import path for mm visual tests (token-management route, low-balance collapse, CDP clicks)**: Putting a freshly deployed ERC20 on its asset page:
  - Import: navigate to `#/token-management` → click `token-management-add-custom-token-button` → type the contract address into `custom-token-import-address-input` (metadata auto-fills after ~2s) → `custom-token-import-submit-button`. - **[ts-023] Patched-build mid-session reload trap — reloadExtension ERR_BLOCKED_BY_CLIENT; relaunch instead**: After a webpack-watch rebuild, `window.stateHooks.reloadExtension()` leaves extension pages permanently `ERR_BLOCKED_BY_CLIENT` (the extension blocks its own origin; retries after 8-20s never recover). For before/after evidence of a fix: capture "before" on the unpatched session (`yarn start:test` webpack watch + `mm launch --state default`, unlock, enable basic functionality, deploy+import token) → apply patch → wait for the recompile (`grep -c "compiled successfully"` increments; incremental ~5-45s) → do NOT call `reloadExtension()`; run `mm cleanup` → `mm launch --state default` again (fresh fixture), then re-run the scripted setup (unlock password `correct horse battery staple`, re-enable basic functionality via CDP, redeploy the token — the deploy address is deterministic for the same sender+nonce, so the seeded address stays valid) → capture "after". `MM_HEADLESS=true` + `MM_ARTIFACTS_DIR=/tmp/...` keep screenshots organized; `mm screenshot <name>` writes to `<artifacts>/screenshots/screenshot-<ts>.png`.
- **[ts-024] Asset-page live-verification learnings (ASSETS-4402 r2–r5) — TanStack retry, deeplinks, CDP network adds, mm session recovery, PR asset upload**:
  - **TanStack Query retry trap**: passing `retry: undefined` explicitly to `useQuery` overrides the query client's `retry: false` default during options merge, silently reintroducing 3 retries with backoff (~7s+). When making retry configurable, only spread the key when set: `...(retry === undefined ? {} : { retry })`. Note `createUIQueryClient` (`ui/contexts/query-client.ts`) sets no retry default; the `retry: false` default exists only inside `@metamask/react-data-query`'s own `useQuery` wrapper — plain `@tanstack/react-query` hooks (e.g. `useTokenAssetQuery`) default to 3 retries. Symptom when tripped: a `waitFor` in a test using the real query client times out after the retries exhaust.
  - **Asset-page deeplinks**: the working form is `#/asset/<caipChainId>/<encodeURIComponent(fullCaipAssetId)>` — the second segment must be URL-encoded; raw slashes/colons silently redirect to `#/`. Also, the token API returns `[]` for some otherwise-known assets (e.g. USDC eip155:1) and the asset page bounces to home for those — for live verification use an asset the API serves (WETH works; MSFT on eip155:4663 works).
  - **Adding networks programmatically via CDP** (`window.stateHooks.submitRequestToBackground`, args array positional): `NetworkController:addNetwork` requires BOTH `defaultRpcEndpointIndex` and `defaultBlockExplorerUrlIndex` (validation fails otherwise). `LegacyBackgroundApiService:setEnabledNetworks` takes a single chainId, not an array. `mm cdp Runtime.evaluate '<json>'` works against the extension page and is the fastest driver.
