# Playbook: MetaMask/metamask-extension

This is an evolving playbook. Rules are structured as itemized bullets with unique IDs to allow for incremental updates and to prevent "context collapse".

## Strategies and Hard Rules (SHR)

These are environment-specific guidelines and mandatory workflows.

- **[shr-001] Environment Setup**: `nvm install && corepack enable && yarn install`, then pin Node to the **literal `.nvmrc` version** (not `nvm current`): `export PATH="$HOME/.nvm/versions/node/v<version>/bin:$PATH"; hash -r`. `nvm use` alone loses to `/exec-daemon/node` (Node 22) on PATH; `$(nvm current)` chained after `nvm install` returns the *pre-install* version — wrong pin fails `yarn install` with `"current Node version X does not satisfy the required version"`. Verify with `node --version` before yarn. Also `export COREPACK_ENABLE_DOWNLOAD_PROMPT=0` (see `[ts-005]`). **Decide with `ls -d node_modules`, not the log**: `/tmp/cursor/async-install/install-user.log` saying `"Started from stale build ..., skipping install script"` means no repo has `node_modules`, but `/tmp/cursor/` may be **missing entirely** (background setup never scheduled) — a missing log is not evidence that install succeeded. Run install in tmux (~1–3 min, redirect to a file) and keep editing while it runs; the repo is fully readable/editable without `node_modules`.
- **[shr-002] Pre-Commit Validation**: Before pushing any code, you must execute `yarn lint:tsc`. Commits are only permitted if this check passes with zero errors.
- **[shr-003] Dependency Upgrade Scoping**: When upgrading dependencies, only modify `package.json` and `yarn.lock`. If TypeScript or lint errors appear in other files, verify they are directly caused by the upgrade before touching them. Pre-existing issues should not be addressed in the upgrade PR.
- **[shr-004] Cloud Task Instructions Priority**: When Cloud Agent instructions require committing, pushing, or running tests, follow those requirements even if repo-level `AGENTS.md` says not to commit/stage by default.
- **[shr-005] Search for in-flight PRs before implementing an issue fix**: Popular MetaMask issues often already have a community PR open. Before coding, run `gh api -X GET search/issues -f q='repo:MetaMask/<repo> is:pr is:open in:title <fix keywords>'` and search the issue number itself (`q='repo:... <issue-number>'`) to catch duplicates; call out any duplicate PR in the summary and PR body so the reviewer can pick.
    - Unquoted `in:title` with the *fix* phrasing (`in:title ERC-1155 transfer amount` found the PR after three keyword searches found nothing).
    - Read the issue number off a matching PR's `Fixes #N` line instead of hunting the issue separately — satisfies `[shr-002]` traceability in one call.

## Useful Code Snippets and Templates (CODE)

Reusable patterns and specific syntax requirements.

- **[code-001] Mocha Type Fix**: When using `it.each` for table-driven tests, prepend the call with a TypeScript override to avoid type-definition errors. _Reference:_ `ui/components/app/alert-system/utils.test.ts`.

  ```typescript
  // @ts-expect-error This is missing from the Mocha type definitions
  it.each([...])
  ```
- **[code-002] Arc / Stable dual-identity gas tokens (USDC, USDT0)**: On Arc (`0x13b2`/`eip155:5042`) the native gas token IS USDC; the same balance also exists as ERC-20 at `0x3600000000000000000000000000000000000000` (Stable: USDT0 at `0x779ded0c9e1022225f8e0630b35a9b54be713736`). Accounts API returns both: native `eip155:5042/slip44:5042` @ 18 decimals, ERC-20 @ 6 decimals, identical amounts, both priced. Never "unify" the two — they are deliberately opposite:
    - Asset-list / send keeps **native**, hides ERC-20 via `ui/components/app/assets/enablement/networks-customization.ts`.
    - Swap / bridge does the reverse: hides **native** via `BRIDGE_ASSET_PICKER_HIDDEN_ASSETS` in `shared/constants/bridge.ts` (router only validated for the ERC-20).
    - Under assets-unify-state the native row is *derived*, not stored: `getAccountTrackerControllerAccountsByChainId` in `shared/lib/selectors/assets-migration.ts` (mirrored in mobile `app/selectors/assets/assets-migration.ts`) emits it only when `AssetsController.assetsInfo[assetId].type === 'native'`, seeded from `packages/assets-controller/src/defaults.ts`. Any filter that removes the ERC-20 must first confirm the native entry is present — otherwise the token drops from the list while `assetsBalance` still counts it (ASSETS-3900).
    - `useArcDefaultTokens` (both clients) imports the ERC-20 id into custom assets, so manual import of `0x3600...` reports `"token already added"`.
- **[code-003] Module-level in-flight request cache**: Reset a de-dup promise with `.finally()` on the *assigned* promise (`refreshPromise ??= doFetch().finally(() => { refreshPromise = undefined; })`), never a `finally` block inside an IIFE. A sync throw in the async prologue makes the inner `finally` run before the assignment, permanently pinning a settled promise so the request never retries. Cover with a "retries after failure" test. _Reference:_ `shared/lib/token-api/supported-networks.ts`.
- **[code-004] assets-unify-state hide invariant**: Hiding a token MUST set `assetPreferences[assetId].hidden` via `AssetsController.hideAsset` (dispatch `actions.hideAsset(toAssetId(address, chainId))`). `removeCustomAsset` is NOT a hide: `shared/lib/selectors/assets-migration.ts` derives `allTokens` from `assetsBalance ∪ customAssets` but derives `allIgnoredTokens` only from `assetPreferences[*].hidden`, and `addCustomAsset` seeds a zero-balance `assetsBalance` entry — assets dropped from `customAssets` stay visible. `@metamask/assets-controllers` `selectAllEvmAssets` / `selectAllMultichainAssets` skip only assets in `allIgnoredTokens` / `allIgnoredAssets`. Mirror `ui/pages/token-management/token-management.tsx`: dispatch `ignoreTokens` / `multichainIgnoreAssets` **and** `hideAsset` unconditionally. Writes gated on compile-time `ASSETS_UNIFIED_STATE_ENABLED` (true in `builds.yml`); reads additionally gated on remote `assetsUnifyState` — write-side bugs reproduce only for rollout users (reads as flakiness in reports). Keep addresses checksummed end-to-end (`normalizeAssetId`, `toChecksumHexAddress`); lowercasing silently breaks the `includes()` filter.

## Troubleshooting and Pitfalls (TS)

Lessons learned from past execution failures or resource constraints.

- **[ts-001] Memory-Efficient Testing**: When running specific tests via `yarn jest <path>`, if the process encounters RAM memory limits, prepend the command with `NODE_OPTIONS=--max-old-space-size=4096`. Note that the full `yarn test` suite is prone to timeouts.
- **[ts-002] Jest Coverage Overhead**: Always append `--coverage=false` when running individual Jest tests to reduce execution time and resource consumption.
- **[ts-003] Ticket attachments unreachable — reconstruct state from public MetaMask APIs**: Jira / Slack attachments cannot be downloaded on a Cursor Cloud VM (Jira attachment REST → 403 without an Atlassian token, Atlassian MCP has no attachment tool, `FetchMcpResource` → 404, Slack DM → `channel_not_found`). Don't burn calls. Pull the address from the ticket and query directly:
    - `https://accounts.api.cx.metamask.io/v5|v6/multiaccount/balances?accountIds=eip155:<chain>:<address>&networks=eip155:<chain>` — exact CAIP-19 asset IDs, decimals, balances the client will persist.
    - `.../v2/accounts/<address>/balances?networks=<decimalChainId>` — v2 shape.
    - `.../v1/supportedNetworks` — chain coverage.
    - `https://price.api.cx.metamask.io/v3/spot-prices?assetIds=<caip19,...>&vsCurrency=usd` — pricing.

    Stronger evidence than a state dump: shows what the controller *will* receive. Note: `$JIRA_INTEGRATION_PLAYBOOK_URL` may hold a **local machine path**, not a URL — probe with `${VAR:0:30}` (full value is redacted in tool output) and skip if not fetchable.
- **[ts-004] Use the Grep tool, not shell `rg`, when match text matters**: `rg` via the Shell tool can return output with *matched substrings replaced* — searching `0x3600...|ARC_USDC|eip155:5042` returned lines where `ARC_USDC_ERC20_TOKEN_ADDRESS` had become `n_ERC20_TOKEN_ADDRESS` and every address / CAIP id had become a bare `n`. Paths and line numbers stay correct, so shell `rg` is still fine for "which files mention this" — never trust it for reading identifiers, addresses, or asset IDs. Use the Grep tool (correct rendering, supports `-C` / `glob` / `type`); fall back to reading the file.
- **[ts-005] Corepack download prompt silently hangs `yarn install`**: On cloud VMs, `corepack enable && yarn install` blocks forever on Corepack's interactive `"Corepack is about to download yarn@x.y.z … Do you want to continue? [Y/n]"` prompt. Piping stdout (e.g. `| tail -40`) hides the prompt — looks like a slow fetch. Always `export COREPACK_ENABLE_DOWNLOAD_PROMPT=0`; prefer the vendored binary via `yarn yarn-binary:hydrate` (`corepack hydrate .yarn/yarn-corepack.tgz --activate`) so no download runs. Diagnose with `ps -o pid,etime,time,args -p <pid>`: `TIME 00:00:00` after many minutes of `ELAPSED` = blocked on stdin, not working. Prefer `yarn install > /tmp/yarn-install.log 2>&1` over piping to `tail` — keeps prompts and progress inspectable.
- **[ts-006] Use `gh api search/issues`, not `gh issue list --search`, on cloud VMs**: Read-only cloud `gh` makes `gh issue list --search "..." --json number,title,url` exit 0 with placeholder rows (`[{"number":0,"title":"","url":""}]`) — silent, not a failure. Use instead: `gh api -X GET search/issues -f q='repo:<owner>/<repo> is:issue <terms>' --jq '.items[] | "\(.number) | \(.state) | \(.title)"'`. Search is fuzzy (quoted `in:title` phrases often ignored); no matches may mean Jira-only — MetaMask webhook reports use `[url|url]` markup and often have no GitHub issue. Then satisfy `[shr-002]` by describing the report in the PR body, not inventing an issue number.
- **[ts-007] `yarn lint:eslint <paths>` is not scoped — it lints the whole repo**: Package script hardcodes `eslint .`, so paths you pass are appended to `.` rather than replacing it. On a fresh cloud VM (cold `node_modules/.cache/eslint` cache) a "3-file lint" takes ~10 min wall / ~12 min CPU and prints nothing until it finishes — looks like a hang. Confirm with `ps -eo pid,etime,time,args | grep eslint` (growing `TIME` column means it is working, not blocked). For scoped linting use `yarn lint:changed:fix` (git-changed files, ~1s for a few files) or call the binary: `NODE_OPTIONS='--max-old-space-size=6144' npx eslint <paths> -c ./.eslintrc.js`. `yarn lint:changed:fix` prints only the oxfmt formatter summary ("Formatting and linting N changed files"); full-repo `yarn lint:eslint` is still the way to be certain ESLint is clean before pushing — budget the time and start it in tmux alongside other work.
