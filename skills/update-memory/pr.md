# PR phase

Goal: open one **draft** PR per pushed branch, whose body is the full audit trail — every open memory-update issue examined for this repo label appears in exactly one of two disjoint sections. Applied issues auto-close on merge via GitHub's [linked-issue keywords](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue); opted-out issues stay open.

## Auto-close mechanics

GitHub auto-closes an issue referenced by a merged PR only when the reference uses a closing keyword: `close`, `closes`, `closed`, `fix`, `fixes`, `fixed`, `resolve`, `resolves`, `resolved`. A bare `#N` reference creates a backlink but does not auto-close.

The skill uses `Closes #N` (title case, one per applied issue) so the intent is obvious to a human reader too.

## Body template

```markdown
## Memory Update Batch — <repo-label>

Automated audit of open `memory-update` issues against `<target-file>`.
Every verdict below was decided by the skill; this PR is the review gate.
Applied issues auto-close on merge; opted-out issues remain open for follow-up.

Curated <N_examined> open issue(s): <N_applied> applied, <N_opted_out> opted out.

### Applied (auto-close on merge)

- Closes #<num> — [<OP> <assigned-id>] "<short title>" — <one-line summary of what changed>
- Closes #<num> — [<OP> <assigned-id>] "<short title>" — <one-line summary of what changed> — _judgement: compressed per style.md (flagged `verbose`)_
- ...

### Opted out (issues remain open)

- #<num> — <reason>. <one-line context, e.g. "canonical is #<other-num>">
- #<num> — <reason>. <one-line context> — _judgement: <what tipped the tiebreaker>_
- ...

### ID assignments

| Issue | Operation | Placeholder | Assigned ID | Section | File |
|-------|-----------|-------------|-------------|---------|------|
| #<num> | ADD    | [ts-NEW]    | [ts-008]    | TS      | MetaMask/metamask-extension.md |
| #<num> | UPDATE | [shr-002]   | [shr-002]   | SHR     | MetaMask/metamask-extension.md |
| ...    | ...    | ...         | ...         | ...     | ...                            |

### Review checklist

- [ ] Every applied bullet reads correctly in context (no ID collisions, no broken sub-bullet indentation).
- [ ] Assigned IDs are sequential from the previous max per section — no gaps, no reuse.
- [ ] Opted-out reasons are accurate; any `dedupe → #N` points at a still-applied canonical.
- [ ] Placeholder-leak grep on the diff is clean: `git diff origin/main -- <file> | rg '\[(shr\|code\|ts)-NEW\]'` returns nothing.
- [ ] Auto-resolved judgement calls (rows marked _judgement_) match what you would have picked.

### Traceability

Generated by the `update-memory` skill (see `skills/update-memory/SKILL.md`). One commit per applied issue for reviewable granularity.
```

## Judgement notes

The skill never pauses to ask, so the PR body has to carry the reasoning that a conversation would otherwise have surfaced. Append a `— _judgement: …_` suffix to any row whose verdict came from a tiebreaker (`dedupe`, `duplicate-target`), a borderline `no-evidence` call, or a non-trivial style compression. One clause, naming what tipped it. Rows with an obvious verdict get no suffix — the marker is only useful if it is rare.

## Invariant check before `gh pr create`

Run the disjointness check. Extract the two lists:

```bash
APPLIED=$(rg -o '^- Closes #(\d+)' -r '$1' body.md | sort -u)
OPTED=$(rg -o '^- #(\d+) —' -r '$1' body.md | sort -u)
COMMON=$(comm -12 <(echo "$APPLIED") <(echo "$OPTED"))
```

If `COMMON` is non-empty, **abort**. The renderer is buggy or the audit table was inconsistent — do not open a PR whose merge would silently close an opted-out issue.

Also verify: every issue in the audit-phase table appears in exactly one of `APPLIED` or `OPTED`. A missing issue is a bug — every examined issue must be accounted for.

## Open the draft PR

```bash
GH_TOKEN="${CLOUD_AGENT_WRITE_ISSUES_PAT:-$GH_TOKEN}" \
  gh pr create \
    --repo Prithpal-Sooriya/Cloud-Agent-Memory \
    --base main \
    --head "$BRANCH" \
    --draft \
    --title "memory: curate <N_applied> update(s) for <repo-label>" \
    --body-file body.md \
    --label memory-update \
    --label "<repo-label>"
```

Notes:

- `--draft` is non-negotiable per the skill's hard rules.
- Labels mirror the source issues so the PR shows up in the same filter as the batch it drains.
- Title uses `memory:` prefix (matches the commit prefix) and names the count so the sidebar communicates scope.

## After the PR opens

- Print the PR URL and the counts (`applied`, `opted-out`).
- Do **not** run `gh pr ready`, `gh pr merge`, or comment on any issue. The human closes the loop.
- Delete the local scratch `body.md` if you wrote one, or keep it under `.git/` — it must not be committed.

## Multi-label sessions

If the curation batch spans multiple repo labels, repeat the whole Apply → PR loop per label. Never combine two labels into one PR; that violates the skill's hard rule and complicates the auto-close semantics (a partial merge would leave one playbook stranded).

Print a final summary listing all PR URLs opened this session.
